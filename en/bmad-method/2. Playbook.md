# BMad Method — Playbook

## Installation & Setup

### Prerequisites

| Requirement | Details |
|---|---|
| **AI IDE** | Claude Code, Cursor, Windsurf, Cline, or any AI IDE |
| **Git** | For version control of documents and code |
| **Node.js** (optional) | If using CLI tools |

### Installation — Claude Code

```bash
# Clone the BMad Method repository
git clone https://github.com/bmadcode/BMAD-METHOD.git

# Copy agent configurations to your project
cp -r BMAD-METHOD/.bmad-core .bmad-core

# Or use the quick-start
npx bmad-method init
```

### Installation — Cursor / Windsurf

```bash
# Same repo, different folder structure
git clone https://github.com/bmadcode/BMAD-METHOD.git

# Copy configurations
cp -r BMAD-METHOD/.bmad-core .bmad-core
```

### Verify Installation

In your AI IDE, try:

```
Use the Analyst agent to analyze this project idea: [your idea]
```

If the agent responds with structured requirements questions → ✅ installation successful.

## Day 1 Workflow — New Project

### Step-by-Step Guide

```bash
# Step 1: Start with analysis
"Analyze this project idea: [your description]"
# → Analyst agent asks clarifying questions
# → Produces PRD document

# Step 2: Planning (if BMad Method track)
"Create user stories from this PRD"
# → PM agent creates stories with acceptance criteria

"Design the UX for these stories"
# → Design Architect creates UX specifications

# Step 3: Solutioning
"Create the architecture for this project"
# → Architect designs tech stack, architecture, APIs

# Step 4: Implementation
"Implement story [story-id]"
# → Developer writes code following architecture
```

### Quick Flow (Small Tasks)

```bash
# For simple tasks — skip directly to implementation
"Quick: Add a dark mode toggle to the settings page"
# → Analyst briefly analyzes → Developer implements
```

### Tips for Day 1

> [!IMPORTANT]
> **Invest time in the Analysis phase.** This is the most important step.
> - Answer clarifying questions thoroughly
> - Describe edge cases and constraints
> - Clarify what's MVP vs future
> - The AI will keep asking until it understands 100%

## Configuration Strategies

### Preset 1: Solo Developer (Quick Iteration)

```
Track: Quick Flow → BMad Method (as project grows)
Agents: Analyst → Developer (initially)
Documents: PRD (light) → Code
```

### Preset 2: Startup Team

```
Track: BMad Method
Agents: Analyst → PM → Architect → Developer → QA
Documents: Full set
Reviews: Architecture review before implementation
```

### Preset 3: Enterprise

```
Track: Enterprise
Agents: Full roster including SRE, DevOps
Documents: Full set + governance docs
Reviews: Multi-stage reviews at each phase
```

## Cheat Sheet

### Agent Quick Reference

| Agent | When to Use | Key Output |
|---|---|---|
| **Analyst** | Project inception, requirement changes | PRD |
| **PM** | User story creation, prioritization | User Stories, Story Map |
| **Design Architect** | UX/UI design needed | Wireframes, UX Specs |
| **Architect** | Technical design decisions | Architecture Doc, API Specs |
| **Developer** | Code implementation | Production Code, Tests |
| **QA** | Testing, validation | Test Results, Bug Reports |
| **DevOps** | Deployment, infrastructure | CI/CD Config, Deployments |
| **Poseidon** | Multi-agent coordination | Workflow State |

### Phase Flow Quick Reference

```
Analysis → Planning → Solutioning → Implementation
   │                                      │
   └──── Quick Flow (skip middle) ────────┘
```

### Document Quick Reference

| Document | Created By | Used By |
|---|---|---|
| PRD | Analyst | PM, Architect |
| User Stories | PM | Architect, Developer |
| UX Specs | Design Architect | Developer |
| Architecture Doc | Architect | Developer, DevOps |
| Test Plan | QA | Developer, QA |

### Scale Decision Quick Reference

| Signal | Track |
|---|---|
| "Fix this bug" | Quick Flow |

## Troubleshooting

### Agent Not Following Process

| Symptom | Check | Fix |
|---|---|---|
| Agent skips analysis | System prompt not loaded | Reload/recopy agent configurations |
| PRD too sparse | Quick Flow track selected | Explicitly request BMad Method track |
| Agent produces generic output | Insufficient context | Provide more project detail in the brief |
| Agent hallucinating features | Requirements not clear | Re-run analysis with more specific constraints |

### Document Issues

| Symptom | Check | Fix |
|---|---|---|
| Template not adaptive | Wrong template version | Update to latest BMad templates |
| Checklist items missing | Template truncated | Reload full template |
| Documents not evolving | Static file approach | Use "update this document" prompts |

### Workflow Issues

| Symptom | Check | Fix |
|---|---|---|
| Phase transitions unclear | Workflow XML not loaded | Verify .bmad-core folder exists |
| Agents not coordinating | Poseidon not active | Explicitly invoke orchestrator |
| Context lost between phases | Documents not saved | Ensure documents are persisted to files |

## Best Practices

### ✅ Gold Rules

1. **Always start with Analysis** — Even for "simple" tasks, a quick analysis catches hidden complexity
2. **Trust the checklists** — They encode hard-won experience about what goes wrong
3. **Scale appropriately** — Don't use Enterprise track for a bug fix
4. **Keep documents living** — Update them as requirements evolve
5. **One agent at a time** — Let each agent complete before moving to the next
6. **Version control documents** — Commit `.bmad-core` docs alongside code

### ❌ Anti-Patterns

| Anti-Pattern | Problem | Better Approach |
|---|---|---|
| Skip analysis, start coding | Requirements gaps surface late, expensive fixes | Always analyze first, even briefly |
| One agent does everything | Quality drops, context overflows | Use specialized agents |
| Static documents | Requirements drift, documents stale | Living documents, regular updates |
| Enterprise track for small task | Overhead kills productivity | Use Quick Flow for small tasks |
| Ignore checklists | Quality issues slip through | Run every checklist, no exceptions |
