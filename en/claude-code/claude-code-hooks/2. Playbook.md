# Claude Code Hooks — Playbook

> [!NOTE]
> This is an **action-oriented** document. Read [[3-Research/Github/Claude Code Hooks/0. Overview]] to understand what Hooks are, [[3-Research/Github/Claude Code Hooks/1. Architecture and Logic]] to understand internal mechanisms.

## Part I: Setup & Environment Configuration

### 1.1. Prerequisites

| Requirement | Details |
|---|---|
| **Claude Code** | Version 1.0.34 or later |
| **Shell** | bash or zsh |
| **Config file** | `.claude/settings.json` (project) or `~/.claude/settings.json` (user) |

### 1.2. Check Claude Code Version

```bash
claude --version
# Must be >= 1.0.34
```

### 1.3. Create Configuration File

```bash
# Project-level hooks (committed to git, shared with team)
mkdir -p .claude
touch .claude/settings.json

# Or personal hooks (not committed)
touch .claude/settings.local.json

# Or global hooks (all projects)
# Edit ~/.claude/settings.json
```

### 1.4. Minimal Configuration

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "echo 'File changed: $CLAUDE_FILE_PATH'"
          }
        ]
      }
    ]
  }
}
```

## Part II: Day 1 — Your First Hook

### 2.1. Auto-Format Code After Every Write

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "prettier --write $CLAUDE_FILE_PATH 2>/dev/null; exit 0"
          }
        ]
      }
    ]
  }
}
```

> [!TIP]
> `exit 0` at the end ensures the hook never blocks even if prettier fails on certain files.

### 2.2. Block Dangerous Commands

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "echo $CLAUDE_TOOL_INPUT | jq -r '.command' | grep -qvE '(rm -rf /|DROP TABLE|format )' || (echo 'Blocked dangerous command' >&2; exit 1)"
          }
        ]
      }
    ]
  }
}
```

### 2.3. Log All Activity

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "echo \"$(date '+%Y-%m-%d %H:%M:%S') | $CLAUDE_TOOL_NAME | $CLAUDE_FILE_PATH\" >> .claude/activity.log"
          }
        ]
      }
    ]
  }
}
```

## Part III: Daily Operations

### 3.1. Common Hook Patterns

#### Auto-Lint TypeScript/JavaScript

```json
{
  "matcher": "Write|Edit",
  "hooks": [{
    "type": "command",
    "command": "if echo $CLAUDE_FILE_PATH | grep -qE '\\.(ts|tsx|js|jsx)$'; then npx eslint --fix $CLAUDE_FILE_PATH 2>/dev/null; fi; exit 0"
  }]
}
```

#### Auto-Run Tests for Changed Files

```json
{
  "matcher": "Write|Edit",
  "hooks": [{
    "type": "command",
    "command": "if echo $CLAUDE_FILE_PATH | grep -qE '\\.test\\.(ts|js)$'; then npx jest $CLAUDE_FILE_PATH --passWithNoTests 2>/dev/null; fi; exit 0"
  }]
}
```

#### Secret Scanning Before File Write

```json
{
  "matcher": "Write",
  "hooks": [{
    "type": "command",
    "command": "echo $CLAUDE_TOOL_INPUT | jq -r '.content' | grep -qE '(AKIA|sk-|ghp_|password\\s*=)' && (echo 'Potential secret detected!' >&2; exit 1) || exit 0"
  }]
}
```

#### Notification via Webhook

```json
{
  "matcher": "",
  "hooks": [{
    "type": "http",
    "url": "https://hooks.slack.com/services/YOUR/WEBHOOK/URL",
    "method": "POST",
    "body": {
      "text": "Claude Code: Task completed"
    }
  }]
}
```

### 3.2. Advanced Patterns

#### Chain Multiple Hooks

```json
{
  "matcher": "Write|Edit",
  "hooks": [
    {
      "type": "command",
      "command": "prettier --write $CLAUDE_FILE_PATH 2>/dev/null; exit 0"
    },
    {
      "type": "command",
      "command": "npx eslint --fix $CLAUDE_FILE_PATH 2>/dev/null; exit 0"
    },
    {
      "type": "command",
      "command": "echo \"$(date) | formatted + linted: $CLAUDE_FILE_PATH\" >> .claude/activity.log"
    }
  ]
}
```

Hooks in an array run **sequentially** — first to last.

#### Conditional Execution by File Type

```bash
#!/bin/bash
# .claude/hooks/format.sh
FILE="$CLAUDE_FILE_PATH"
EXT="${FILE##*.}"

case "$EXT" in
  py) black "$FILE" 2>/dev/null ;;
  ts|tsx|js|jsx) prettier --write "$FILE" 2>/dev/null ;;
  go) gofmt -w "$FILE" 2>/dev/null ;;
  rs) rustfmt "$FILE" 2>/dev/null ;;
esac

exit 0
```

```json
{
  "matcher": "Write|Edit",
  "hooks": [{
    "type": "command",
    "command": "bash .claude/hooks/format.sh"
  }]
}
```

## Part IV: Configuration Strategy

### 4.1. Team Configuration (Project-level)

```json
// .claude/settings.json (committed to git)
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          { "type": "command", "command": "prettier --write $CLAUDE_FILE_PATH 2>/dev/null; exit 0" }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "bash .claude/hooks/security-gate.sh" }
        ]
      }
    ]
  }
}
```

### 4.2. Personal Configuration (Local)

```json
// .claude/settings.local.json (NOT committed)
{
  "hooks": {
    "Stop": [
      {
        "matcher": "",
        "hooks": [
          { "type": "command", "command": "osascript -e 'display notification \"Claude done!\" with title \"Claude Code\"'" }
        ]
      }
    ]
  }
}
```

### 4.3. Global Configuration

```json
// ~/.claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          { "type": "command", "command": "echo \"$(date) | $CLAUDE_FILE_PATH\" >> ~/.claude/global-activity.log" }
        ]
      }
    ]
  }
}
```

## Part V: Cheat Sheet

### Event Types

| Event | When | Can Block? | Common Use |
|---|---|---|---|
| `SessionStart` | Session starts | ❌ | Init environment |
| `PreToolUse` | Before tool use | ✅ | Security gates, validation |
| `PostToolUse` | After tool use | ❌ | Format, lint, log |
| `Notification` | Notification sent | ❌ | External alerts |
| `Stop` | Turn ends | ❌ | Summary, metrics |

### Handler Types

| Type | Mechanism | Example |
|---|---|---|
| `command` | Shell command | `prettier --write $FILE` |
| `http` | HTTP request | Webhook to Slack |
| `llm` | LLM evaluation | Code review check |

### Environment Variables

| Variable | Available In | Content |
|---|---|---|
| `$CLAUDE_TOOL_NAME` | Pre/PostToolUse | Tool name |
| `$CLAUDE_TOOL_INPUT` | Pre/PostToolUse | JSON input |
| `$CLAUDE_FILE_PATH` | PostToolUse (Write/Edit) | File path |
| `$CLAUDE_SESSION_ID` | All | Session ID |
| `$CLAUDE_PROJECT_DIR` | All | Project root |

### Matchers

| Matcher | Matches |
|---|---|
| `"Write"` | File writes |
| `"Edit"` | File edits |
| `"Bash"` | Shell commands |
| `"Write\|Edit"` | Writes and edits |
| `""` | Everything |

## Part VI: Troubleshooting

### 6.1. Hooks Not Running

| Cause | Fix |
|---|---|
| Claude Code version < 1.0.34 | Update: `claude update` |
| Invalid JSON in settings file | Validate JSON syntax |
| Wrong settings file location | Check path: `.claude/settings.json` |
| Matcher doesn't match tool | Check matcher value against tool name |

### 6.2. Hook Command Fails

| Cause | Fix |
|---|---|
| Command not found | Use full path or ensure tool is installed |
| Permission denied | `chmod +x` on script files |
| Environment variable empty | Check event type supports that variable |

### 6.3. Hook Blocking Unexpectedly

| Cause | Fix |
|---|---|
| Script exits with non-zero in PreToolUse | Add `exit 0` at end for non-blocking behavior |
| grep returns non-zero when no match | Use `grep ... || true` pattern |
| Piped command fails | Add error handling to each pipe stage |

### 6.4. Performance Issues

| Issue | Fix |
|---|---|
| Hook too slow | Optimize script, add caching |
| Too many hooks fire | Use specific matchers instead of empty |
| Formatter takes too long | Run async or batch |

## Part VII: Best Practices

### ✅ Gold Rules

1. **Always `exit 0` for non-blocking hooks** — Prevent accidental blocking
2. **Redirect stderr on non-critical tools** — `2>/dev/null` when failure is acceptable
3. **Use scripts for complex logic** — Don't cram everything into one JSON line
4. **Test hooks before deploying** — Run commands manually first
5. **Separate team vs personal hooks** — `.claude/settings.json` vs `.claude/settings.local.json`
6. **Log judiciously** — Too much logging = noise, too little = blind spots
7. **Security hooks in PreToolUse only** — It's the only event that can block

### ❌ Anti-Patterns

| Anti-Pattern | Problem | Better Approach |
|---|---|---|
| Forgetting `exit 0` on PostToolUse hooks | Unnecessary error noise | Always end with `exit 0` |
| Putting secrets in hook commands | Exposed in config files | Use environment variables |
| Heavy processing in every hook | Slows down Claude | Filter by file type, cache results |
| No error handling | Silent failures | Log errors, handle edge cases |
| Same hook in all 3 config files | Runs 3 times | Place in one appropriate scope |
