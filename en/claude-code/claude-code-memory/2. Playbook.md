# Claude Code Memory — Playbook

## 1. Installation & Setup

### 1.1. Create Project CLAUDE.md (Fastest)

**Method 1: Use `/init` command**

```bash
# In terminal, open Claude Code
claude

# In session, run:
/init
```

Claude will automatically create `CLAUDE.md` (or `.claude/CLAUDE.md`) with a template suitable for the project.

**Method 2: Create manually**

```bash
# Create at project root
touch CLAUDE.md

# Or in .claude/ directory
mkdir -p .claude
touch .claude/CLAUDE.md
```

### 1.2. Basic CLAUDE.md Structure

```markdown
# Project Instructions

## Tech Stack
- TypeScript + Node.js
- PostgreSQL + Prisma ORM
- React 19 + Next.js 15

## Coding Standards
- Use 2-space indentation
- Prefer `const` over `let`
- All functions must have JSDoc comments
- Use barrel exports (index.ts) for modules

## Testing
- Run `npm test` before committing
- Unit tests go in `__tests__/` alongside source files
- Use `vitest` for testing

## Architecture
- API handlers live in `src/api/handlers/`
- Database models in `src/models/`
- Shared utilities in `src/utils/`

## Git Workflow
- Branch naming: `feature/`, `fix/`, `chore/`
- Commit messages follow Conventional Commits
- Always rebase before merging
```

### 1.3. Setup User-Level CLAUDE.md

```bash
# Create user CLAUDE.md — applies to ALL projects
mkdir -p ~/.claude
cat > ~/.claude/CLAUDE.md << 'EOF'
# Personal Coding Preferences

- Prefer functional programming style
- Use TypeScript strict mode
- Always add error handling
- Prefer named exports over default exports
- Use descriptive variable names (no abbreviations)
EOF
```

### 1.4. Setup Rules Directory

```bash
# Create rules structure for project
mkdir -p .claude/rules

# Create rule files
cat > .claude/rules/code-style.md << 'EOF'
# Code Style Guidelines
- Use 2-space indentation
- Max line length: 100 characters
- Use trailing commas in multi-line structures
EOF

cat > .claude/rules/testing.md << 'EOF'
---
paths:
  - "tests/**/*.test.ts"
  - "**/*.spec.ts"
---
# Testing Conventions
- One assertion per test when possible
- Use descriptive test names: "should [action] when [condition]"
- Mock external dependencies, not internal modules
EOF

cat > .claude/rules/api-design.md << 'EOF'
---
paths:
  - "src/api/**/*.ts"
---
# API Development Rules
- All API endpoints must include input validation
- Use the standard error response format
- Include OpenAPI documentation comments
- Always return proper HTTP status codes
EOF
```

### 1.5. Setup Auto Memory

Auto memory is **enabled by default**. To check:

```bash
# In Claude Code session:
/memory
```

**Disable auto memory (if needed):**

```json
// .claude/settings.json
{
  "autoMemoryEnabled": false
}
```

Or use environment variable:

```bash
CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 claude
```

**Step-by-step:**

```bash
# 1. Initialize project
mkdir my-project && cd my-project
git init

# 2. Open Claude Code and init
claude
# In session: /init
# Claude creates CLAUDE.md automatically

# 3. Edit CLAUDE.md to add project-specific rules
# (edit with regular editor or ask Claude)

# 4. Create rules directory for path-scoped rules
mkdir -p .claude/rules
# Create rule files as in section 1.4

# 5. Commit
git add CLAUDE.md .claude/
git commit -m "chore: add Claude Code memory configuration"

# 6. Start coding — Claude already has context!

# 7. End of day: review auto memory
# In session: /memory
```

### 2.2. Brownfield Project (Existing Project)

```bash
# 1. Open project and run Claude
cd existing-project
claude

# 2. Ask Claude to analyze the project
# "Analyze this project's tech stack and coding patterns, then create a CLAUDE.md"

# 3. Claude will:
#    - Read package.json, tsconfig.json, etc.
#    - Analyze directory structure
#    - Create appropriate CLAUDE.md

# 4. Review and edit CLAUDE.md

# 5. Create additional rules if needed
mkdir -p .claude/rules
# ...

# 6. Commit
git add CLAUDE.md .claude/
git commit -m "chore: add Claude Code memory for existing project"
```

### 2.3. Team Onboarding

```bash
# Team lead already committed CLAUDE.md to repo
git pull

# Each team member just needs to:

# → Everyone follows the same conventions

# Add personal preferences (not committed):
cat > ~/.claude/CLAUDE.md << 'EOF'
# My personal preferences that don't go in the repo
- I prefer verbose explanations
- Always show git diff before committing
EOF
```


```
├── packages/

│   │   └── .claude/rules/
│   │       └── react.md        # React-specific rules
│   │
│   └── backend/
│       ├── CLAUDE.md           # Backend team rules
│       └── .claude/rules/
│           └── api.md          # API-specific rules
│
└── shared/
    └── .claude/rules/
```

**Monorepo exclusion config:**

```json
// packages/frontend/.claude/settings.local.json
{
  "claudeMdExcludes": [
    "**/backend/CLAUDE.md",
    "**/backend/.claude/rules/**"
  ]
}
```

### 4.4. Cross-Project Rules Sharing

```bash
# Create shared rules directory
mkdir -p ~/shared-claude-rules
cat > ~/shared-claude-rules/typescript.md << 'EOF'
# TypeScript Standards
- Always use strict mode
- Prefer type over interface for object types
- Use discriminated unions for state management
EOF

# Symlink into each project
cd project-a
ln -s ~/shared-claude-rules .claude/rules/shared

cd project-b
ln -s ~/shared-claude-rules .claude/rules/shared

# Or symlink individual files
ln -s ~/company-standards/security.md .claude/rules/security.md
```

## 5. Cheat Sheet

### 5.1. Commands & Flags

| Command / Flag | Description | Example |
|---|---|---|
| `/init` | Create CLAUDE.md for project | `/init` |
| `/memory` | View/edit auto memory | `/memory` |
| `/compact` | Compact conversation (keeps CLAUDE.md) | `/compact` |
| `--add-dir` | Load CLAUDE.md from additional dir | `claude --add-dir ../shared` |

### 5.2. File Locations

| File | Path | Commit to Git? |
|---|---|---|
| Project CLAUDE.md | `./CLAUDE.md` | ✅ |
| Alt project CLAUDE.md | `./.claude/CLAUDE.md` | ✅ |
| Project rules | `./.claude/rules/*.md` | ✅ |
| Project settings | `./.claude/settings.json` | ✅ |
| Local settings | `./.claude/settings.local.json` | ❌ (gitignore) |
| User CLAUDE.md | `~/.claude/CLAUDE.md` | ❌ (personal) |
| User rules | `~/.claude/rules/*.md` | ❌ (personal) |
| Auto memory | `~/.claude/projects/<proj>/memory/` | ❌ (auto) |
| Managed policy | `/Library/.../ClaudeCode/CLAUDE.md` | ❌ (IT managed) |

### 5.3. CLAUDE.md Syntax

| Syntax | Description | Example |
|---|---|---|
| `@file` | Import file content | `@README` |
| `@path/to/file.md` | Import specific file | `@docs/standards.md` |
| `@~/path` | Import from home dir | `@~/.claude/my-rules.md` |
| `# Heading` | Section header | `# Code Standards` |
| `- item` | Rule/instruction | `- Use 2-space indent` |

### 5.4. Settings

| Setting | Value | Description |
|---|---|---|
| `autoMemoryEnabled` | `true`/`false` | Enable/disable auto memory |
| `claudeMdExcludes` | `["glob"]` | Exclude CLAUDE.md files |

### 5.5. Environment Variables

| Variable | Value | Description |
|---|---|---|
| `CLAUDE_CODE_DISABLE_AUTO_MEMORY` | `1` | Disable auto memory |
| `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD` | `1` | Enable `--add-dir` CLAUDE.md loading |

## 6. Troubleshooting

| # | Error | Cause | Fix |
|---|---|---|---|
| 1 | Claude doesn't follow CLAUDE.md | File not loaded / wrong location | Run `/memory` to verify loaded files. Check file is in correct location (see Cheat Sheet 5.2) |
| 2 | Instructions too generic | "Format code properly" is too vague | Write specifically: "Use 2-space indentation for all TypeScript files" |
| 3 | Conflicts between CLAUDE.md files | 2 files give contradictory instructions | Review all loaded files, remove conflicting rules |
| 4 | CLAUDE.md too large (>200 lines) | One file contains too many rules | Split using `@imports` or move to `.claude/rules/` |
| 5 | Instructions lost after `/compact` | Instructions only said in chat | Persist into CLAUDE.md file — chat instructions don't survive compact |
| 6 | Auto memory saved wrong info | Claude misunderstood correction | Run `/memory` → review → delete wrong entry |
| 7 | Don't know what auto memory saved | Memory operates "silently" | Run `/memory` to audit. Or read directly from `~/.claude/projects/<proj>/memory/` |
| 8 | Rules not applying to file type | `paths:` pattern is wrong | Check glob pattern. Use `**/*.ts` instead of `*.ts` for deep matching |
| 9 | Monorepo loading wrong CLAUDE.md | Other team's CLAUDE.md conflicts | Use `claudeMdExcludes` in `.claude/settings.local.json` |
| 10 | `--add-dir` not loading CLAUDE.md | Missing env var | Set `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` |

### Debugging Checklist

```bash
# 1. Verify loaded files
/memory  # in Claude Code session

# 2. Check CLAUDE.md exists
ls -la CLAUDE.md .claude/CLAUDE.md .claude/rules/ 2>/dev/null

# 3. Check auto memory storage
ls -la ~/.claude/projects/*/memory/

# 4. Check settings
cat .claude/settings.json 2>/dev/null
cat .claude/settings.local.json 2>/dev/null

# 5. Check excludes
grep -r "claudeMdExcludes" .claude/ 2>/dev/null
```

## 7. Best Practices

### ✅ Gold Rules

| # | Rule | Reason |
|---|---|---|
| 1 | **Keep CLAUDE.md under 200 lines** | > 200 lines reduces instruction adherence |
| 2 | **Write specific instructions** | "Use 2-space indent" > "Format code nicely" |
| 3 | **Commit CLAUDE.md to Git** | Team-wide consistency + audit trail |
| 4 | **Use `.claude/rules/` for modular rules** | Separation of concerns, path-scoped |
| 5 | **Review auto memory regularly** | `/memory` weekly — delete wrong entries |
| 6 | **Persist important info into CLAUDE.md** | Don't only say it in chat — it will be lost after `/compact` |
| 7 | **Gitignore `.claude/settings.local.json`** | Personal settings shouldn't be committed |
| 8 | **Use `@imports` for long docs** | Keep CLAUDE.md concise, reference external |
| 9 | **Path-scope rules when possible** | Avoid applying irrelevant rules |
| 10 | **Test instructions** | Ask Claude "What are the rules for X?" to verify |

### ❌ Anti-Patterns

| # | Anti-Pattern | Consequence | Alternative |
|---|---|---|---|
| 1 | CLAUDE.md > 500 lines | Claude misses instructions | Split into `@imports` + `.claude/rules/` |
| 2 | Vague instructions | Claude interprets arbitrarily | Specific, actionable, with examples |
| 3 | Only use chat instructions | Lost after `/compact` or new session | Write into CLAUDE.md |
| 4 | Never review auto memory | Memory accumulates noise | `/memory` review weekly |
| 5 | Conflicting rules | Claude picks arbitrarily | Audit cross-file conflicts |
| 6 | Commit `settings.local.json` | Overrides teammate's settings | Add to `.gitignore` |
| 7 | Too many non-path-scoped rules | Frontend rules apply to backend | Use `paths:` frontmatter |
| 8 | Copy-paste CLAUDE.md between projects | Outdated, inconsistent | Symlinks or shared rules directory |

### Strategy for Writing Effective CLAUDE.md

```markdown
# ✅ GOOD — Specific, actionable
- Use 2-space indentation
- Run `npm test` before committing
- API handlers live in `src/api/handlers/`
- Error responses follow format: { error: { code, message } }
- Use `zod` for input validation in API routes

# ❌ BAD — Vague, not actionable
- Format code properly
- Test your changes
- Keep files organized
- Handle errors correctly
- Validate inputs
```
