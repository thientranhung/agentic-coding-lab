# Claude Code Skills — Playbook

## Part I: Setup

### 1.1. Check Prerequisites

```bash
# Verify Claude Code is installed
claude --version

# Skills directory (personal)
ls ~/.claude/skills/

# Skills directory (project)
ls .claude/skills/
```

### 1.2. Create First Skill

```bash
# Create skill directory
mkdir -p ~/.claude/skills/my-first-skill

# Create SKILL.md
cat > ~/.claude/skills/my-first-skill/SKILL.md << 'EOF'
---
name: my-first-skill
description: "Use when the user asks to create a new React component"
---

# React Component Skill

## Process
1. Create component file with TypeScript
2. Add Props interface
3. Use functional component with arrow syntax
4. Export as default
5. Create co-located test file

## Template
```tsx
interface Props {
  // Define props here
}

const ComponentName: React.FC<Props> = ({ }) => {
  return (
    <div>
      {/* Component content */}
    </div>
  );
};

export default ComponentName;
```
EOF
```

### 1.3. Verify Skill Loaded

Start a new Claude session and try:
```
Create a new React component for a user profile card
```

If Claude mentions "Using my-first-skill" → ✅ success.

## Part II: Creating Skills

### 2.1. Skill Template

```markdown
---
name: skill-name
description: "Use when [specific triggering conditions]"
---

# Skill Name

## Overview
Core principle in 1-2 sentences.

## When to Use
- Symptom A
- Symptom B
- NOT for: [exclusions]

## The Process
[Steps, flowcharts, checklists]

## Red Flags
[Signs to STOP and reassess]

## Common Mistakes
[Anti-patterns and fixes]

## Integration
[Links to related skills]
```

### 2.2. Description Best Practices

| ✅ Good | ❌ Bad |
|---|---|
| "Use when debugging test failures" | "A debugging skill" |
| "Use when creating new API endpoints" | "API development" |
| Start with "Use when..." | Summarize the workflow |
| Include symptoms and contexts | Generic description |

### 2.3. Adding Supporting Files

```
skills/
  my-complex-skill/
    SKILL.md              # Main reference
    examples.md           # Usage examples
    checklist.md          # Detailed checklist
    helper-script.sh      # Automation script
```

## Part III: Daily Operations

### Using Skills

Skills auto-trigger based on task context. You don't need to explicitly call them:

```
"Debug this failing test"
→ Claude auto-invokes systematic-debugging skill

"Build a new authentication feature"
→ Claude auto-invokes brainstorming skill
```

### Force a Specific Skill

```
"Use the brainstorming skill for this task"
```

### Override Plugin Skill

```
# If personal and plugin skills have same name:
"Use superpowers:brainstorming"  # Force plugin version
```

## Part IV: Cheat Sheet

### Skill Locations

| Location | Type |
|---|---|
| `~/.claude/skills/` | Personal (Claude Code) |
| `.claude/skills/` | Project-shared |
| `plugin/skills/` | Plugin-bundled |

### SKILL.md Frontmatter

| Field | Required | Example |
|---|---|---|
| `name` | ✅ | `my-skill` |
| `description` | ✅ | `"Use when debugging React hooks"` |

### Priority Order

```
User instructions (CLAUDE.md) > Skills > System prompt
Personal skills > Plugin skills (same name)
```

## Part V: Troubleshooting

### Skill Not Triggering

| Cause | Fix |
|---|---|
| Description doesn't match task | Rewrite description with better triggering conditions |
| SKILL.md not in correct location | Check directory: `skills/<name>/SKILL.md` |
| Frontmatter syntax error | Validate YAML frontmatter |
| CLAUDE.md overriding | Check if CLAUDE.md has conflicting instructions |
| New session needed | Restart Claude session |

### Skill Behaving Differently

| Cause | Fix |
|---|---|
| Personal skill shadowing plugin | Use `plugin-name:skill-name` to force |
| Description too broad | Narrow triggering conditions |
| Rigid skill being adapted | Mark as rigid in instructions |

## Part VI: Best Practices

### ✅ Gold Rules

1. **Start description with "Use when..."** — Focus on triggering conditions
2. **Keep skills focused** — One skill = one technique/workflow
3. **Include "NOT for" section** — Prevent false triggers
4. **Add red flags** — Signs Claude should stop and reassess
5. **Test with real scenarios** — Verify skill triggers correctly
6. **Use checklists** — TodoWrite integration for tracking progress

### ❌ Anti-Patterns

| Anti-Pattern | Problem | Better Approach |
|---|---|---|
| Skill description summarizes workflow | Claude follows description instead of body | Focus on triggering conditions only |
| Too many skills | Context overload | Keep focused, merge related skills |
| No "NOT for" section | False positive triggers | Explicitly exclude non-applicable scenarios |
| Putting everything in one skill | Too broad, unreliable | Split into focused skills |
