# Claude Code Sub-agents — Playbook

## Part I: Setup

### 1.1. Prerequisites

| Requirement | Details |
|---|---|
| **Claude Code** | Latest version with sub-agent support |
| **Platform** | Claude Code (full support), Codex (partial) |

### 1.2. Creating Custom Agents

```bash
# Create agents directory
mkdir -p .claude/agents

# Create a custom agent
cat > .claude/agents/code-reviewer.md << 'EOF'
You are a specialized code reviewer.

## Review Checklist
1. Check for security vulnerabilities
2. Verify error handling is complete
3. Ensure test coverage exists
4. Check code style consistency
5. Look for performance issues

## Output Format
Report findings as:
- CRITICAL: [description] in [file:line]
- HIGH: [description] in [file:line]
- MEDIUM: [description] in [file:line]
- LOW: [description] in [file:line]
EOF
```

### 1.3. Verify Agent Available

```
/agents
# Should list your custom agents
```

## Part II: Using Sub-agents

### 2.1. Automatic Sub-agent Usage

Frameworks like GSD and Superpowers automatically dispatch sub-agents. You don't need to manually invoke them.

### 2.2. Manual Sub-agent Invocation

```
"Use the code-reviewer agent to review the changes in src/auth/"
```

### 2.3. Common Patterns

#### Code Review

```
"Dispatch a code review sub-agent for the last 3 commits"
```

#### Parallel Implementation

```
"Create sub-agents to implement these three independent features in parallel:
1. User profile page
2. Settings page  
3. Dashboard widgets"
```

#### Specialized Analysis

```
"Use a read-only sub-agent to analyze the performance characteristics of src/database/"
```

## Part III: Creating Effective Agents

### 3.1. Agent Definition Template

```markdown
You are a [role description].

## Your Expertise
- [Domain 1]
- [Domain 2]

## Your Process
1. [Step 1]
2. [Step 2]
3. [Step 3]

## Output Format
[Describe expected output format]

## Boundaries
- DO: [what to do]
- DON'T: [what to avoid]
```

### 3.2. Example Agents

#### Test Writer Agent

```markdown
You are a test-writing specialist.

## Process
1. Read the implementation file
2. Identify testable behaviors (not implementation details)
3. Write tests for each behavior
4. Ensure edge cases are covered
5. Run tests to verify they pass

## Test Style
- Use descriptive test names
- One assertion per test when possible
- Arrange-Act-Assert pattern
- Mock external dependencies only
```

#### Documentation Agent

```markdown
You are a documentation specialist.

## Process
1. Read the source code
2. Identify public APIs and interfaces
3. Write clear JSDoc/docstrings
4. Create usage examples
5. Update README if needed

## Style
- Use present tense
- Start descriptions with verbs
- Include @param, @returns, @throws
- Add usage examples for complex APIs
```

## Part IV: Cheat Sheet

### Agent Locations

| Location | Scope |
|---|---|
| `.claude/agents/` | Project-level |
| Plugin `agents/` | Plugin-bundled |

### Status Codes

| Status | Meaning | Controller Action |
|---|---|---|
| `DONE` | Success | Proceed |
| `DONE_WITH_CONCERNS` | Success with notes | Review concerns |
| `NEEDS_CONTEXT` | Missing info | Provide context |
| `BLOCKED` | Cannot proceed | Assess and fix |

### Permission Modes

| Mode | Read | Write | Execute |
|---|---|---|---|
| Full | ✅ | ✅ | ✅ |
| Read-only | ✅ | ❌ | ❌ |
| Custom | ⚙️ | ⚙️ | ⚙️ |

## Part V: Troubleshooting

### Agent Not Found

| Cause | Fix |
|---|---|
| Wrong file location | Ensure `.claude/agents/<name>.md` |
| File not .md extension | Use `.md` extension |
| Session needs refresh | Reload or start new session |

### Agent Producing Poor Results

| Cause | Fix |
|---|---|
| Prompt too vague | Add specific instructions and examples |
| Task too large | Break into smaller sub-tasks |
| Wrong model | Use more capable model for complex tasks |
| Missing context | Include relevant file paths in dispatch |

### Agent Blocked

| Cause | Fix |
|---|---|
| Missing file access | Check permissions |
| Task unclear | Rewrite with clearer requirements |
| External dependency | Provide the dependency or mock it |

## Part VI: Best Practices

### ✅ Gold Rules

1. **Fresh context per task** — Don't reuse sub-agents across tasks
2. **Clear, specific prompts** — Include file paths, constraints, expected output
3. **Single responsibility** — Each agent does one thing well
4. **Review sub-agent output** — Don't blindly trust, especially for critical code
5. **Use read-only for analysis** — Prevent accidental modifications during review
6. **Status protocol** — Always check sub-agent status before proceeding
7. **Escalate blocked agents** — Don't retry indefinitely

### ❌ Anti-Patterns

| Anti-Pattern | Problem | Better Approach |
|---|---|---|
| Huge task for one sub-agent | Context overflow, poor quality | Split into smaller tasks |
| No review after implementation | Bugs slip through | Always dispatch reviewer |
| Parallel conflicting tasks | File conflicts | Ensure tasks are independent |
| Ignoring BLOCKED status | Wastes time on retries | Assess and fix root cause |
