# How Claude Code Works — Playbook

## Installation & Setup

### Installing Claude Code

```bash
# macOS / Linux
npm install -g @anthropic-ai/claude-code

# Verify installation
claude --version

# Login
claude /login
```

### Setting Up a New Project

```bash
# Navigate to project
cd /path/to/your/project

# Initialize CLAUDE.md — wizard-guided
claude
# In the session, type:
/init
```

### Basic Configuration

**1. Project CLAUDE.md** — `./CLAUDE.md` or `./.claude/CLAUDE.md`:

```markdown
# Project Instructions

## Tech Stack
- Node.js 20, TypeScript 5.3
- React 18 with Next.js 14
- PostgreSQL 16

## Conventions
- Use 2-space indentation
- Run `npm test` before committing
- API handlers live in `src/api/handlers/`
- Use `snake_case` for database fields, `camelCase` for TypeScript

## Testing
- Unit tests: `npm test`
- E2E tests: `npm run test:e2e`
- Coverage minimum: 80%
```

**2. Personal CLAUDE.md** — `~/.claude/CLAUDE.md`:

```markdown
# Personal Preferences
- Always explain changes before making them
- Use Vietnamese for comments when possible
- Prefer functional programming patterns
```

**3. Permission Settings** — `.claude/settings.json`:

```json
{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git status)",
      "Bash(git diff *)",
      "Bash(git log *)",
      "Read"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Bash(git push *)"
    ]
  }
}
```

## Day 1 Workflow

### Step 1: First Launch

```bash
# Open terminal, navigate to project
cd ~/my-project

# Run Claude Code
claude

# Claude will automatically read codebase structure
# Type /init to create CLAUDE.md if it doesn't exist
/init
```

### Step 2: Get Familiar with the Codebase

```
# In the Claude Code session, ask:
Explain the architecture of this project. What are the main modules and how do they interact?

# Claude will automatically:
# 1. Read file structure
# 2. Read README, package.json, config files
# 3. Scan source code
# 4. Respond with diagrams/explanations
```

### Step 3: First Task — Bug Fix

```
# Provide specific context:
The checkout flow is broken for users with expired cards. 
Check src/payments/ for the issue, especially token refresh. 
Write a failing test first, then fix it.

# Claude will:
# 1. Read src/payments/
# 2. Write a failing test
# 3. Fix the bug
# 4. Run tests to verify
```

### Step 4: Review and Commit

```
# Review changes Claude made
Show me a summary of all changes you made.

# Commit
Commit the changes with a descriptive message.
```

### Step 5: Evaluate the Session

```
# See what Claude has learned
/memory

# Compact conversation if it's long
/compact focus on the payment fix we just did
```

## Daily Operations

### Starting a New Day

```bash
# Continue yesterday's session
claude --continue

# Or choose a specific session
claude --resume

# Or start a new session
claude
```

### Effective Work Patterns

#### Pattern 1: Explore → Plan → Execute

```
# Step 1: Explore (Plan mode — Shift+Tab twice)
Read src/auth/ and understand how we handle sessions. 
Then create a plan for adding OAuth support.

# Step 2: Review plan
# Claude presents plan, you review

# Step 3: Execute (switch back to Default mode)
Go ahead and implement the plan.
```

#### Pattern 2: Test-Driven Development

```
# Write test first
Implement validateEmail. 
Test cases: 'user@example.com' → true, 'invalid' → false, '@domain.com' → false. 
Write tests first, then implement, then run tests.
```

#### Pattern 3: Multi-file Refactoring

```
# Delegate to Claude
Refactor the user module to use the Repository pattern. 
Move database queries from controllers to a new UserRepository class.
Keep all existing tests passing.
```

#### Pattern 4: Code Review

```
# Review PR changes
Review the changes in the current branch compared to main. 
Focus on security issues, performance problems, and code quality.
```

### Using Sub-agents

```
# Delegate complex task
Run the full test suite in a subagent while we continue working on the API.

# Research in background
Have a subagent research how to implement WebSocket support 
and write a summary in docs/websocket-plan.md.
```

### CLI Automation

```bash
# One-shot task (non-interactive)
claude -p "Write unit tests for src/utils/validator.ts"

# Pipe input
cat error.log | claude -p "Analyze these errors and suggest fixes"

# Batch operations
git diff main --name-only | claude -p "Review these changed files for security issues"

# Monitor logs
tail -f app.log | claude -p "Alert me if you see any anomalies"
```

|:---|:---|

### Permission Rule Quick Reference

| Rule | Meaning |
|:---|:---|
| `Bash` | Match all bash commands |
| `Bash(npm run *)` | Match `npm run` + any subcommand |
| `Bash(git commit *)` | Allow git commits |
| `Read` | Match all file reads |
| `Read(./.env)` | Match reading specific .env file |
| `Edit` | Match all file edits |
| `WebFetch(domain:*.com)` | Match fetch from domain pattern |
| `Agent` | Match subagent spawning |

## Troubleshooting

### Common Errors

| Error | Cause | Fix |
|:---|:---|:---|
| Context window full | Session too long, too many files | `/compact`, start new session, or use subagents |
| Claude not following CLAUDE.md | File not loaded correctly, vague instructions | Check file location, write more specifically, use `/init` |
| Auto memory saves incorrect info | Claude misunderstood patterns | `/memory` → edit/delete incorrect entries |
| CLAUDE.md too large | Too many instructions in 1 file | Split into `.claude/rules/` files, use `@import` |
| Instructions lost after `/compact` | Instructions only in conversation | Place in CLAUDE.md — always reloads each session |
| Permission blocked | Rules in settings blocking tool | `/permissions` to review, fix settings.json |
| Tool denied but needed | Deny rule too broad | Add a more specific allow rule (allow > deny for specific) |
| Old session not found | Session cleaned up | Increase `cleanupPeriodDays` in settings |
| Git conflict when Claude edits | Multiple sessions on same branch | Use git worktrees for parallel sessions |
| Claude runs wrong command | Lacking project context | Update CLAUDE.md with correct commands |
| MCP server won't connect | Wrong config or server down | `/mcp` to debug, check server process |
| Subagent fails | Task too complex or narrow context | Break task down, provide clearer context |

## Best Practices

### ✅ Gold Rules

| Rule | Explanation |
|:---|:---|
| **Be specific upfront** | Provide file paths, test cases, expected behavior from the start |
| **Delegate, don't dictate** | Give direction, let Claude find the way — `"Fix the bug in payments"` > `"Open file X, go to line Y, change Z"` |
| **Explore before implementing** | Use Plan mode (`Shift+Tab` 2x) for complex tasks |
| **Write specific CLAUDE.md** | Actionable instructions, not vague |
| **Use subagents for parallel tasks** | Research, tests, documentation — delegate separately |
| **`/compact` frequently** | Keep context clean, focus on current task |
| **Review auto memory** | `/memory` periodically to ensure Claude learns correctly |
| **Git worktrees for parallel work** | Each worktree = 1 separate Claude session |
| **Interrupt when needed** | `Esc` to stop, adjust direction — Claude adapts quickly |
| **Verify with tests** | Always request running tests after code changes |

### ❌ Anti-patterns

| Anti-pattern | Why It's Bad | Alternative |
|:---|:---|:---|
| Vague prompts | Claude has to guess, wastes tokens | Provide specific context |
| Not using CLAUDE.md | Loses context each session | Write CLAUDE.md for the project |
| `dontAsk` mode for daily work | Loses control | Use `default` or `acceptEdits` |
| Sessions too long | Context window overflow | Start new session, use `/compact` |
| Dictating every step | Doesn't leverage agentic capabilities | Delegate outcomes, don't micromanage |
| Ignoring auto memory | Claude may save incorrect info | Review `/memory` periodically |
| Not using tests | No way to verify | Request writing tests before/after |
| Large copy-paste into prompt | Wastes context | Let Claude read files itself |

### Advanced Tips

**1. Conversation steering:**
```
That's not quite right. The issue is in the session handling, not the auth middleware.
```
→ Redirect Claude without needing to restart

**2. Incremental complexity:**
```
# Session 1: Basic feature
Add a user profile page with name and email.

# Session 2: Enhance
Add avatar upload to the profile page we created.
```

**3. Structured prompts for large tasks:**
```
I need to add OAuth support. Here's what I'm thinking:
1. Use passport.js
2. Support Google and GitHub providers
3. Store tokens in the existing user table
4. Add login/callback routes

Read the existing auth code in src/auth/ first, then propose any changes to this plan.
```

**4. Automation pipeline:**
```bash
# Daily code quality check
claude -p "Run linter, fix any issues, run tests, and create a summary report in QUALITY.md"

# PR automation
claude -p "Review the diff against main, write a PR description, and commit with a good message"
```
