# Playbook — Gemini CLI

## Installation & Setup

### System Requirements

| Requirement | Details |
|---|---|
| **Node.js** | ≥20.0.0 (recommended ~20.19.0 for development) |
| **OS** | macOS, Linux, Windows |
| **RAM** | Minimum 4GB |
| **Network** | Internet connection required (calls Gemini API) |

### Quick Install

#### Option 1: npx (no install needed)

```bash
npx @google/gemini-cli
```

#### Option 2: npm global

```bash
npm install -g @google/gemini-cli
```

#### Option 3: Homebrew (macOS/Linux)

```bash
brew install gemini-cli
```

#### Option 4: MacPorts (macOS)

```bash
sudo port install gemini-cli
```

#### Option 5: Anaconda (restricted environments)

```bash
# Create new environment
conda create -y -n gemini_env -c conda-forge nodejs
conda activate gemini_env

# Install Gemini CLI
npm install -g @google/gemini-cli
```

### Choose Release Channel

```bash
# Stable (default) — recommended
npm install -g @google/gemini-cli@latest

# Preview — try new features early
npm install -g @google/gemini-cli@preview

# Nightly — bleeding edge
npm install -g @google/gemini-cli@nightly
```

### Authentication Setup

#### Method 1: Google OAuth (Recommended — Free)

```bash
# Just run gemini and select "Sign in with Google"
gemini
# → Select OAuth flow → Browser opens automatically → Login → Done
```

#### Method 2: API Key

```bash
# Get key at https://aistudio.google.com/apikey
export GEMINI_API_KEY="YOUR_API_KEY"
gemini
```

#### Method 3: Vertex AI (Enterprise)

```bash
export GOOGLE_API_KEY="YOUR_API_KEY"
export GOOGLE_GENAI_USE_VERTEXAI=true
gemini
```

#### Method 3b: Vertex AI with Code Assist License

```bash
export GOOGLE_CLOUD_PROJECT="YOUR_PROJECT_ID"
gemini
# → Select "Sign in with Google"
```

### Sandboxing Setup (Recommended)

```bash
# macOS — Seatbelt (built-in, no additional install needed)
echo "GEMINI_SANDBOX=true" >> ~/.env

# Linux/Windows — Docker
echo "GEMINI_SANDBOX=docker" >> ~/.env

# Or use Podman
echo "GEMINI_SANDBOX=podman" >> ~/.env
```

## Day 1 Workflow

### Starting with an Existing Project

```bash
# 1. cd into project
cd ~/projects/my-app

# 2. (Optional) Create GEMINI.md to customize behavior
cat > GEMINI.md << 'EOF'
# Project Context
This is a Next.js 14 app with TypeScript, Prisma ORM, and TailwindCSS.

## Coding Conventions
- Use functional components with hooks
- Follow ESLint/Prettier config
- Write tests for all new features
- Use absolute imports from @/

## Do NOT
- Modify database schema without asking
- Install new dependencies without confirmation
EOF

# 3. Run Gemini CLI
gemini

# 4. Start interacting
> Explain the architecture of this project
> What are the main components and how do they relate?
```

### Starting a New Project

```bash
# 1. Create new folder
mkdir my-new-project && cd my-new-project

# 2. Run Gemini CLI
gemini

# 3. Describe project
> Create a REST API with Express and TypeScript that manages a todo list.
> Include authentication, rate limiting, and PostgreSQL with Prisma.

# 4. Gemini will create files, install dependencies, and set up the project for you
```

### Headless Mode for Scripting

```bash
# Simple text response
gemini -p "Explain the architecture of this codebase"

# JSON output for parsing
gemini -p "List all functions in src/" --output-format json

# Streaming JSON for monitoring
gemini -p "Run tests and fix all failures" --output-format stream-json

# With specific model
gemini -m gemini-2.5-flash -p "Refactor this function for performance"
```

## Daily Operations

### Effective Usage Patterns

#### Code Review

```bash
gemini
> Review the last 5 commits for potential issues:
> - Security vulnerabilities
> - Performance problems
> - Code style violations
```

#### Debugging

```bash
gemini
> This test is failing: npm test -- src/auth/login.test.ts
> Can you figure out why and fix it?
```

#### Refactoring

```bash
gemini
> Refactor the user service to use the repository pattern.
> Keep backward compatibility with existing API.
```

#### Multi-directory Context

```bash
# Add directories to context
gemini --include-directories ../shared-lib,../docs

> How does the shared library's auth module work?
> Update our service to use the new API.
```

### MCP Server Integration

#### Setup MCP Servers

Create/edit file `~/.gemini/settings.json`:

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_TOKEN": "ghp_YOUR_TOKEN"
      }
    },
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/documents"]
    },
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": {
        "DATABASE_URL": "postgresql://user:pass@localhost:5432/mydb"
      }
    }
  }
}
```

#### Using MCP Tools

```bash
gemini
> @github List my open pull requests
> @github Create an issue titled "Refactor auth module"
> @postgres Show me the schema of the users table
```

### GitHub Actions Integration

```yaml
# .github/workflows/gemini-review.yml
name: Gemini CLI Review
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: google-github-actions/run-gemini-cli@v1
        with:
          prompt: "Review this PR for code quality, security issues, and suggest improvements"
```

## Strategic Configuration

### Project-level GEMINI.md

```markdown
# GEMINI.md — Place at project root

## Project Identity
This is [Project Name], a [description].

## Tech Stack
- Runtime: Node.js 20
- Framework: Express 5
- Database: PostgreSQL + Prisma
- Testing: Vitest + Supertest

## Conventions
- Use ESM modules (import/export)
- Follow Conventional Commits
- All new code must have tests

## Architecture
- `src/routes/` — API endpoints
- `src/services/` — Business logic
- `src/repositories/` — Data access
- `src/middleware/` — Express middleware
```

### Global GEMINI.md

```bash
# ~/.gemini/GEMINI.md — Applies to ALL projects
cat > ~/.gemini/GEMINI.md << 'EOF'
# Global Preferences
- Always use TypeScript
- Prefer functional programming patterns
- Write comprehensive error handling
- Include JSDoc comments for public APIs
EOF
```

### Custom Commands

Create file `.gemini/commands/review.toml`:

```toml
[command]
description = "Review code changes"

[command.prompt]
text = """
Review the following changes for:
1. Security vulnerabilities
2. Performance issues
3. Code quality
4. Test coverage gaps

Focus on: $input
"""
```

Usage: `gemini -c "review the latest commit"`

## Cheat Sheet

### CLI Commands

| Command | Description |
|---|---|
| `gemini` | Start interactive mode |
| `gemini -p "prompt"` | Non-interactive, run then exit |
| `gemini -m gemini-2.5-flash` | Select specific model |
| `gemini --include-directories ../lib` | Add context directories |
| `gemini --output-format json` | JSON output |
| `gemini --output-format stream-json` | Streaming JSON events |
| `gemini -c "command-name"` | Run custom command |

### Slash Commands (in interactive mode)

| Command | Description |
|---|---|
| `/help` | Display all commands |
| `/chat` | Open new chat session |
| `/clear` | Clear conversation history |
| `/save` | Save current checkpoint |
| `/restore` | Restore from checkpoint |
| `/model` | Switch model |
| `/tools` | List available tools |
| `/stats` | Usage statistics |
| `/bug` | Report bug |

### Keyboard Shortcuts

| Key | Function |
|---|---|
| `Enter` | Send prompt |
| `Ctrl+C` | Cancel current operation |
| `Ctrl+D` | Exit Gemini CLI |
| `↑` / `↓` | Navigate history |
| `Tab` | Autocomplete |

|---|---|
| `GEMINI_API_KEY` | API key from AI Studio |

| Pattern | Example |

## Troubleshooting

| Error | Cause | Fix |
|---|---|---|
| `EACCES: permission denied` | No permission for global install | `sudo npm install -g @google/gemini-cli` or fix npm permissions |
| `Node.js version not supported` | Node < 20 | Install Node.js ≥20: `nvm install 20` |
| `Authentication failed` | Token expired or wrong key | `gemini` → re-select auth method |
| `Rate limit exceeded` | Exceeded 60 req/min or 1000 req/day | Wait for reset (1 min or 1 day), or upgrade plan |
| `GEMINI_API_KEY is not set` | Env variable not set | `export GEMINI_API_KEY="your-key"` |
| `Sandbox error` | Docker/Podman not installed or not running | `docker ps` to check, or `GEMINI_SANDBOX=false` |
| `MCP server not connecting` | Wrong config or server crash | Check `~/.gemini/settings.json`, try `npx` command manually |
| `GEMINI.md not loaded` | File in wrong location | Place at project root, verify exact name `GEMINI.md` |
| `0.0% success rate` | Invalid API key or model unavailable | Check `GEMINI_API_KEY`, try different model |
| `Context too large` | Files too large | Use `.gitignore` patterns, reduce `--include-directories` |
| `Tool execution timeout` | Shell command running too long | Cancel with `Ctrl+C`, run shorter commands |
| `Cannot find module` | Build error (development) | `npm run clean && npm install && npm run build` |

## Best Practices

### ✅ Gold Rules

| Rule | Explanation |
|---|---|
| **Use GEMINI.md** | Place in each project to customize agent behavior |
| **Enable Sandboxing** | Always enable sandbox when agent runs shell commands |
| **Use Plan Mode** | For complex tasks, let the model plan before executing |
| **Review tool calls** | Read carefully before approving write/edit/shell actions |
| **Checkpoint frequently** | `/save` before major changes |
| **Small prompts** | Break down tasks, specific prompts over vague ones |
| **Specify model** | Use `flash` for quick tasks, `pro` for complex reasoning |

### ❌ Anti-patterns

| Anti-pattern | Why it's bad | Alternative |
|---|---|---|
| **Vague prompts** | "Fix my code" → model doesn't know what to fix | "Fix the null pointer in `getUserById` at line 42" |
| **Blindly approving everything** | May overwrite important files | Read diff before approving |
| **Not using GEMINI.md** | Agent doesn't understand conventions | Create GEMINI.md with project context |
| **Skipping sandbox** | Shell commands run directly on system | `GEMINI_SANDBOX=true` or `docker` |
| **Too much context** | Wastes tokens, reduces performance | Only include necessary directories |
| **Not checkpointing** | Lose progress if errors occur | `/save` frequently |
| **Using nightly in production** | May have breaking bugs | Use `@latest` for production work |

### Advanced Tips

1. **MCP for team workflow**: Set up shared MCP servers for database queries, deployment, monitoring
2. **GitHub Actions automation**: Automatically review PRs, triage issues, generate changelogs
3. **Headless CI/CD**: Use `gemini -p` in CI pipelines for code analysis
4. **Multi-project**: Use global `~/.gemini/GEMINI.md` for shared preferences, project-level for specifics
5. **Token caching**: Enable token caching for repeated queries on the same codebase

## Development & Contributing

### Setup Development Environment

```bash
# Clone repo
git clone https://github.com/google-gemini/gemini-cli.git
cd gemini-cli

# Use correct Node.js version
nvm use  # Reads .nvmrc → Node.js ~20.19.0

# Install dependencies
npm install

# Build all
npm run build

# Run dev mode
npm run start

# Run tests
npm run test

# Full validation (before submitting PR)
npm run preflight
```
