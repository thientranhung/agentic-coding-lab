# Gemini CLI vs Claude Code — Equivalence Comparison

> This document helps developers using **Claude Code** quickly find equivalent commands/capabilities in **Gemini CLI**, and vice versa. Each section includes notes on differences.

## Quick Overview

| Criteria | Gemini CLI | Claude Code |
|---|---|---|
| **Developer** | Google | Anthropic |
| **Open-source** | ✅ Apache 2.0 | ❌ Closed-source |
| **Model** | Gemini 3 (Flash / Pro) | Claude 3.7 Sonnet |
| **Context window** | 1M tokens | 200K tokens (expandable) |
| **Free tier** | 60 req/min, 1,000 req/day | ❌ Paid (Max plan / API) |
| **Runtime** | Node.js ≥20 | Node.js |
| **Package** | `@google/gemini-cli` | `@anthropic-ai/claude-code` |
| **Binary** | `gemini` | `claude` |
| **License** | Apache 2.0 | Proprietary |

## 1. Startup & Session Management

| Function | Claude Code | Gemini CLI | Notes |
|---|---|---|---|
| **Start interactive** | `claude` | `gemini` | ✅ Equivalent |
| **One-shot prompt** | `claude -p "prompt"` | `gemini -p "prompt"` | ✅ Equivalent |
| **Select model** | `claude --model claude-sonnet-4-6` | `gemini -m gemini-2.5-flash` | ✅ Equivalent |
| **Continue last session** | `claude --continue` | ❌ Not available | Gemini doesn't save sessions |
| **Select old session** | `claude --resume` | ❌ Not available | — |
| **Fork session** | `claude --continue --fork-session` | ❌ Not available | — |
| **Add directory context** | `claude --add-dir ../lib` | `gemini --include-directories ../lib` | ✅ Equivalent |
| **Pipe input** | `cat file \| claude -p "analyze"` | `cat file \| gemini -p "analyze"` | ✅ Equivalent |
| **JSON output** | ❌ Not built-in | `gemini -p "..." --output-format json` | 🟢 Gemini stronger |
| **Streaming JSON** | ❌ Not built-in | `gemini -p "..." --output-format stream-json` | 🟢 Gemini stronger |

> **Commentary:** Claude Code is stronger in **session management** — can continue, resume, fork sessions. Gemini CLI is stronger in **structured output** for scripting/automation.

## 3. Context Files — Project Instructions

Both have a "context files" system to customize agent behavior per project, but the mechanisms differ significantly.

| Function | Claude Code | Gemini CLI | Notes |
|---|---|---|---|
| **Project context** | `CLAUDE.md` or `.claude/CLAUDE.md` | `GEMINI.md` | ✅ Equivalent concept |
| **Global context** | `~/.claude/CLAUDE.md` | `~/.gemini/GEMINI.md` | ✅ Equivalent |
| **Enterprise context** | `/etc/claude-code/CLAUDE.md` | ❌ Not available | 🔵 Claude-specific |
| **Subdirectory context** | `foo/CLAUDE.md` (auto-load) | ❌ Not available | 🔵 Claude more flexible |
| **Import files** | `@import README.md` | ❌ Not available | 🔵 Claude-specific |
| **Rules system** | `.claude/rules/*.md` | ❌ Not available | 🔵 Claude-specific |
| **Auto memory** | `MEMORY.md` — auto-learns patterns | ❌ Not available | 🔵 Claude self-learns |
| **Custom commands** | `.claude/commands/` (Skills) | `.gemini/commands/*.toml` | ✅ Both have it, different format |

### Context Files Structure Comparison

```
# Claude Code                          # Gemini CLI
~/.claude/CLAUDE.md          ←→        ~/.gemini/GEMINI.md
./CLAUDE.md                  ←→        ./GEMINI.md
./.claude/CLAUDE.md          ←→        (same GEMINI.md at root)
./.claude/rules/*.md         ←→        ❌ not available
./.claude/commands/          ←→        ./.gemini/commands/*.toml
~/.claude/projects/*/memory/ ←→        ❌ no auto memory
```

> **Commentary:** Claude Code has a much richer memory system — 4-level hierarchy, `@import`, auto memory, rules system. Gemini CLI is simpler — only 2 levels (global + project).

| **Read multiple files** | Call `Read` multiple times | `read-many-files` (batch) | 🟢 Gemini more efficient |

| **Create file** | `Create` tool | `write-file` tool | ✅ Equivalent |
| **Run shell** | `Bash` tool | `shell` tool | ✅ Equivalent |
| **Find file by pattern** | `Search` (file pattern) | `glob` tool | ✅ Equivalent |

| **List directory** | Via `Bash(ls)` | `ls` tool (built-in, dedicated) | 🟢 Gemini has dedicated tool |
| **Web fetch** | `WebFetch` tool | `web-fetch` tool | ✅ Equivalent |
| **Web search** | `WebSearch` (Brave/Google) | `web-search` (Google Search grounding) | ✅ Both have it |
| **Code intelligence** | Plugins (types, refs, definitions) | ❌ Not built-in | 🔵 Claude via plugins |
| **Memory/save info** | Auto Memory (automatic) | `memoryTool` (manual) | Different mechanisms |
| **Plan mode** | `Shift+Tab` 2x → Plan mode | `enter-plan-mode` / `exit-plan-mode` | ✅ Both have it |
| **Ask user** | Asks within agentic loop | `ask-user` tool (dedicated) | 🟢 Gemini has dedicated tool |
| **Skills/commands** | Skill engine + `/command` | `activate-skill` tool | ✅ Both have it |
| **JIT context** | ❌ Not available | `jit-context` tool | 🟢 Gemini-specific |
| **TODO tracking** | ❌ Not built-in | `write-todos` tool | 🟢 Gemini-specific |
| **Internal docs** | ❌ Not available | `get-internal-docs` tool | 🟢 Gemini-specific |
| **Omission detection** | ❌ Not available | `omissionPlaceholderDetector` | 🟢 Gemini blocks lazy output |
| **Diff utilities** | ❌ Built-in (unclear) | `diff-utils` (dedicated module) | 🟢 Gemini-specific |

> **Commentary:** Gemini CLI has **more detailed built-in tools** (20+ tools), while Claude Code has **fewer tools but supplements with plugins, subagents, and hooks**.

## 10. Summary — Unique Strengths

### 🟢 Gemini CLI is Stronger at

| Strength | Details |
|---|---|
| **Generous free tier** | 1,000 req/day, no credit card needed |
| **1M token context** | No need for `/compact`, read entire large codebases |
| **Structured output** | `--output-format json` and `stream-json` for scripting |
| **Multi-sandbox** | Seatbelt + Docker + Podman — flexible per platform |
| **Diverse installation** | npm, Homebrew, MacPorts, Conda, npx |
| **A2A server** | Agent-to-Agent protocol (experimental) |
| **SDK package** | Public SDK for programmatic integration |
| **Token caching** | Optimize token usage for repeated queries |
| **Omission detection** | Block model from writing lazy placeholder output |
| **Google Search grounding** | Real-time search built-in |
| **Open-source** | Apache 2.0 — fork, modify, contribute |

### 🔵 Claude Code is Stronger at

| Strength | Details |
|---|---|
| **Multi-interface** | Terminal, VS Code, JetBrains, Desktop, Web, Mobile, Slack |
| **Session management** | Continue, resume, fork sessions |
| **Auto memory** | Self-learns patterns & preferences cross-sessions |
| **Memory hierarchy** | 4 levels: Enterprise → User → Project → Subdirectory |
| **Granular permissions** | Allow/Ask/Deny rules per tool, managed settings |
| **Automatic git checkpoints** | Safety net without manual action |
| **Subagents** | Delegate tasks in parallel to specialized agents |
| **Hooks** | Event-driven automation (pre-commit, post-edit) |
| **Plugins & marketplace** | Code intelligence, type checking, refs |
| **`/compact` + `/context`** | Proactive context window management |
| **`/init` wizard** | Guided context file creation |
| **Chrome extension** | Interact with browser context |

## Migration Quick Reference

### From Claude Code → Gemini CLI

```bash
# 1. Install
npm install -g @google/gemini-cli

# 2. Convert CLAUDE.md → GEMINI.md
cp CLAUDE.md GEMINI.md
# (Content stays the same — both read Markdown instructions)

# 3. Convert global context
cp ~/.claude/CLAUDE.md ~/.gemini/GEMINI.md

# 4. Config MCP servers
# From: ~/.claude/settings.json → ~/.gemini/settings.json
# mcpServers format is similar

# 5. Change habits
# claude -p "prompt"  →  gemini -p "prompt"
# claude --continue   →  ❌ (start new session)
# /compact            →  ❌ (1M context, not needed)
# Esc (undo)          →  /restore
# Shift+Tab           →  ❌ (confirm each tool call)
```

### From Gemini CLI → Claude Code

```bash
# 1. Install
npm install -g @anthropic-ai/claude-code

# 2. Convert GEMINI.md → CLAUDE.md
cp GEMINI.md CLAUDE.md

# 3. Change habits
# gemini -p "prompt"           →  claude -p "prompt"
# gemini -m model              →  claude --model model
# /save                        →  automatic (git checkpoint)
# /restore                     →  Esc (undo)
# --output-format json         →  ❌ (pipe output manually)
# gemini --include-directories →  claude --add-dir
```
