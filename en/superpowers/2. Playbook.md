## Part I: Installation & Setup

### 1.1. Claude Code — Installation

#### Option A: Via Plugin (Recommended)

```bash
# Install from marketplace (when available)
/plugin install superpowers@marketplace-name
```

#### Option B: Manual Installation

```bash
# Clone the repo
git clone https://github.com/obra/superpowers.git

# Copy to your project
cp -r superpowers/.claude/skills/ .claude/skills/
cp superpowers/.claude/CLAUDE.md .claude/CLAUDE.md
```

#### Option C: Git Submodule

```bash
git submodule add https://github.com/obra/superpowers.git .superpowers
# Then symlink or copy relevant files
```

### 1.2. Cursor — Installation

```bash
# Copy rules files
cp -r superpowers/.cursor/ .cursor/
```

### 1.3. Codex — Installation

```bash
# Copy skills and agent config
cp -r superpowers/.codex/ .codex/
cp -r superpowers/skills/ skills/
```

### 1.4. OpenCode — Installation

```bash
# Copy agent config
cp -r superpowers/.agent/ .agent/
```

### 1.5. Verify Installation

In your IDE, try:

```
Create a new utility function to format phone numbers
```

If the AI mentions "Using tdd-workflow" and writes tests first → ✅ installation successful.

## Part II: Day 1 Workflow

### 2.1. Your First TDD Task

```bash
# Step 1: Describe what you need
"Create a function that validates email addresses"

# Expected AI behavior:
# 1. Reads tdd-workflow skill
# 2. Writes test first:
#    - test_valid_email
#    - test_invalid_email
#    - test_edge_cases
# 3. Runs tests → confirms FAIL
# 4. Writes implementation
# 5. Runs tests → confirms PASS
```

### 2.2. Your First Debugging Task

```bash
# Give the AI a failing test or error
"This test is failing: [paste error]"

# Expected AI behavior:
# 1. Reads systematic-debugging skill
# 2. Reads FULL error output
# 3. Forms ≥3 hypotheses
# 4. Tests hypotheses systematically
# 5. Applies targeted fix
# 6. Runs defense-in-depth check
```

### 2.3. Tips for Day 1

> [!IMPORTANT]
> **Trust the process.** It may feel slow at first (writing tests before code feels "backwards"). But after Day 1, you'll notice:
> - Fewer bugs
> - Faster debugging
> - More confident refactoring
> - Better code quality overall

## Part III: Daily Operations

### 3.1. Common Tasks

#### New Feature

```
"Add user authentication using JWT"
→ Triggers: brainstorming → tdd-workflow → implementation
```

#### Bug Fix

```
"Fix: login fails when username contains @"
→ Triggers: systematic-debugging → root-cause-tracing
```

#### Refactoring

```
"Refactor the database module to use connection pooling"
→ Triggers: tdd-workflow (tests first) → implementation → code-review
```

#### Code Review

```
"Review the changes in src/auth/ for security issues"
→ Triggers: code-review (two-stage)
```

### 3.2. Working with Subagents

For complex tasks:

```
"Implement the payment processing module with Stripe integration"
→ AI should:
1. Brainstorm subagent → approaches
2. Implementation subagent → code (TDD)
3. Spec review subagent → spec compliance
4. Quality review subagent → code quality
```

## Part IV: Configuration Strategies

### 4.1. Project-Level Customization

Modify `.claude/CLAUDE.md` to customize:

```markdown
# Project-specific overrides

## Testing
- Use Vitest instead of Jest
- Use React Testing Library for UI tests
- Minimum coverage: 80%

## Coding Style
- Use functional components only
- Prefer composition over inheritance
- Use TypeScript strict mode
```

### 4.2. Skill Customization

Override any skill by creating the same skill name in your project:

```bash
# Override brainstorming skill
mkdir -p .claude/skills/brainstorming
cat > .claude/skills/brainstorming/SKILL.md << 'EOF'
---
name: brainstorming
description: Use when exploring solutions for complex problems
---
# Custom Brainstorming Process
[Your custom process here]
EOF
```

Personal skills automatically shadow plugin/framework skills.

## Part V: Cheat Sheet

### Skill Triggers

| Skill | Triggered When |
|---|---|
| **tdd-workflow** | Any coding task (always) |
| **systematic-debugging** | Test failure, bug report, error |
| **brainstorming** | Complex decision, multiple approaches possible |
| **implementation** | Coding task after brainstorming |
| **rethinking** | Current approach not working |
| **code-review** | Review request, PR review |
| **root-cause-tracing** | Can't find bug cause |
| **defense-in-depth** | After fixing a bug |
| **find-polluter** | Tests pass alone, fail together |
| **testing-strategy** | Planning test approach |
| **documentation** | Writing docs, README |

### TDD Quick Reference

```
1. Write test → 2. Run (FAIL ❌) → 3. Implement → 4. Run (PASS ✅) → 5. Refactor → 6. Run (PASS ✅)
```

### Subagent Status Codes

| Code | Meaning |
|---|---|
| `DONE` | Proceed to review |
| `DONE_WITH_CONCERNS` | Review concerns |
| `NEEDS_CONTEXT` | Provide info |
| `BLOCKED` | Assess and fix |

### Debugging Flow

```
Error → Read full output → 3+ hypotheses → Test hypotheses → Fix → Defense-in-depth
```

## Part VI: Troubleshooting

### Skills Not Triggering

| Cause | Fix |
|---|---|
| CLAUDE.md not loaded | Check file exists in correct location |
| Skills directory missing | Verify `skills/` or `.claude/skills/` exists |
| Wrong platform config | Check platform-specific paths |
| Session needs refresh | Restart IDE session |

### AI Skips TDD

| Cause | Fix |
|---|---|
| CLAUDE.md overriding | Check for conflicting instructions |
| Task too simple for AI | Explicitly request: "Follow TDD workflow" |
| Model doesn't support skills | Use Claude Code with Sonnet/Opus |

### Subagent Issues

| Issue | Fix |
|---|---|
| Subagent stuck | Check BLOCKED status, provide more context |
| Review too strict | Adjust review criteria in skill config |
| No brainstorming | Explicitly ask for brainstorming phase |

### Test-Related Issues

| Issue | Fix |
|---|---|
| Tests too brittle | Use behavior-based testing, not implementation details |
| Tests too slow | Mock external dependencies |
| Tests pass but code wrong | Add more edge case tests |
| Find polluter needed | Use `find-polluter.sh` script |

## Part VII: Best Practices

### ✅ Gold Rules

1. **Never skip TDD.** Even for "simple" changes. Especially for "simple" changes.
2. **Trust the 1% rule.** If a skill might be relevant, let it trigger.
3. **Use subagents for complex tasks.** Fresh context = better quality.
4. **Always brainstorm before implementing.** At least for non-trivial tasks.
5. **Defense-in-depth after every bug fix.** Don't fix just the symptom.
6. **Read full error output.** Don't skim — AI should read every line.
7. **Review subagent output.** Trust but verify.

### ❌ Anti-Patterns

| Anti-Pattern | Problem | Better Approach |
|---|---|---|
| "This is too simple for TDD" | Simple changes cause unexpected bugs | Always TDD |
| Fixing the obvious without root cause | Whack-a-mole debugging | Systematic debugging |
| Huge task for one context | Quality degrades | Break into subagent tasks |
| Only testing happy path | Edge cases blow up in production | Cover error paths and edge cases |
| Skipping brainstorming | First approach often not the best | Always brainstorm for complex tasks |
