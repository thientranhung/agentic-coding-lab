# Claude Code Memory — Playbook

## 1. Cài đặt & Thiết lập

### 1.1. Tạo Project CLAUDE.md (Nhanh nhất)

**Cách 1: Dùng `/init` command**

```bash
# Trong terminal, mở Claude Code
claude

# Trong session, chạy:
/init
```

Claude sẽ tự tạo `CLAUDE.md` (hoặc `.claude/CLAUDE.md`) với template phù hợp cho project.

**Cách 2: Tạo thủ công**

```bash
# Tạo ở project root
touch CLAUDE.md

# Hoặc trong .claude/ directory
mkdir -p .claude
touch .claude/CLAUDE.md
```

### 1.2. Cấu trúc CLAUDE.md cơ bản

```markdown
# Project Instructions

## Tech Stack
- TypeScript + Node.js
- PostgreSQL + Prisma ORM
- React 19 + Next.js 15

## Coding Standards
- Use 2-space indentation
- Prefer `const` over `let`
- All functions must have JSDoc comments
- Use barrel exports (index.ts) for modules

## Testing
- Run `npm test` before committing
- Unit tests go in `__tests__/` alongside source files
- Use `vitest` for testing

## Architecture
- API handlers live in `src/api/handlers/`
- Database models in `src/models/`
- Shared utilities in `src/utils/`

## Git Workflow
- Branch naming: `feature/`, `fix/`, `chore/`
- Commit messages follow Conventional Commits
- Always rebase before merging
```

### 1.3. Setup User-Level CLAUDE.md

```bash
# Tạo user CLAUDE.md — apply cho TẤT CẢ projects
mkdir -p ~/.claude
cat > ~/.claude/CLAUDE.md << 'EOF'
# Personal Coding Preferences

- Prefer functional programming style
- Use TypeScript strict mode
- Always add error handling
- Prefer named exports over default exports
- Use descriptive variable names (no abbreviations)
EOF
```

### 1.4. Setup Rules Directory

```bash
# Tạo rules structure cho project
mkdir -p .claude/rules

# Tạo rule files
cat > .claude/rules/code-style.md << 'EOF'
# Code Style Guidelines
- Use 2-space indentation
- Max line length: 100 characters
- Use trailing commas in multi-line structures
EOF

cat > .claude/rules/testing.md << 'EOF'
---
paths:
  - "tests/**/*.test.ts"
  - "**/*.spec.ts"
---
# Testing Conventions
- One assertion per test when possible
- Use descriptive test names: "should [action] when [condition]"
- Mock external dependencies, not internal modules
EOF

cat > .claude/rules/api-design.md << 'EOF'
---
paths:
  - "src/api/**/*.ts"
---
# API Development Rules
- All API endpoints must include input validation
- Use the standard error response format
- Include OpenAPI documentation comments
- Always return proper HTTP status codes
EOF
```

### 1.5. Setup Auto Memory

Auto memory **bật sẵn** mặc định. Kiểm tra:

```bash
# Trong Claude Code session:
/memory
```

**Tắt auto memory (nếu cần):**

```json
// .claude/settings.json
{
  "autoMemoryEnabled": false
}
```

Hoặc dùng environment variable:

```bash
CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 claude
```

**Step-by-step:**

```bash
# 1. Khởi tạo project
mkdir my-project && cd my-project
git init

# 2. Mở Claude Code và init
claude
# Trong session: /init
# Claude tạo CLAUDE.md tự động

# 3. Edit CLAUDE.md thêm project-specific rules
# (sửa bằng editor thường hoặc nhờ Claude)

# 4. Tạo rules directory cho path-scoped rules
mkdir -p .claude/rules
# Tạo các rule files như phần 1.4

# 5. Commit
git add CLAUDE.md .claude/
git commit -m "chore: add Claude Code memory configuration"

# 6. Bắt đầu code — Claude đã có context!

# 7. Cuối ngày: review auto memory
# Trong session: /memory
```

### 2.2. Brownfield Project (Dự án có sẵn)

```bash
# 1. Mở project và chạy Claude
cd existing-project
claude

# 2. Nhờ Claude phân tích project
# "Analyze this project's tech stack and coding patterns, then create a CLAUDE.md"

# 3. Claude sẽ:
#    - Đọc package.json, tsconfig.json, etc.
#    - Phân tích cấu trúc thư mục
#    - Tạo CLAUDE.md phù hợp

# 4. Review và chỉnh sửa CLAUDE.md

# 5. Tạo additional rules nếu cần
mkdir -p .claude/rules
# ...

# 6. Commit
git add CLAUDE.md .claude/
git commit -m "chore: add Claude Code memory for existing project"
```

### 2.3. Team Onboarding

```bash
# Team lead đã commit CLAUDE.md vào repo
git pull

# Mỗi team member chỉ cần:
claude
# → CLAUDE.md tự động load
# → Mọi người follow cùng conventions

# Thêm personal preferences (không commit):
cat > ~/.claude/CLAUDE.md << 'EOF'
# My personal preferences that don't go in the repo
- I prefer verbose explanations
- Always show git diff before committing
EOF
```

## 4. Configuration chiến lược

### 4.1. Solo Developer Setup

```
~/
├── .claude/
│   ├── CLAUDE.md           # Global personal preferences
│   └── rules/
│       ├── preferences.md  # Coding style
│       └── workflows.md    # Preferred workflows
│
└── projects/
    └── my-app/
        ├── CLAUDE.md       # Project-specific rules
        └── .claude/
            └── rules/
                ├── api.md  # API conventions
                └── tests.md # Testing rules
```

### 4.2. Small Team Setup

```
project/
├── CLAUDE.md                    # Shared team conventions (committed)
├── .claude/
│   ├── CLAUDE.md               # Alternative location (committed)
│   ├── settings.json           # Shared settings (committed)
│   ├── settings.local.json     # Personal overrides (gitignored)
│   └── rules/
│       ├── code-style.md       # Team code style (committed)
│       ├── api-design.md       # API rules (committed)
│       └── testing.md          # Testing rules (committed)
│
└── .gitignore                   # Include: .claude/settings.local.json
```

### 4.3. Enterprise / Monorepo Setup

```
/Library/Application Support/ClaudeCode/
└── CLAUDE.md                    # Org-wide policy (IT deployed)

monorepo/
├── CLAUDE.md                    # Monorepo-wide rules
├── .claude/
│   └── rules/
│       ├── security.md         # Company security standards
│       └── compliance.md       # Compliance requirements
│
├── packages/
│   ├── frontend/
│   │   ├── CLAUDE.md           # Frontend team rules
│   │   └── .claude/rules/
│   │       └── react.md        # React-specific rules
│   │
│   └── backend/
│       ├── CLAUDE.md           # Backend team rules
│       └── .claude/rules/
│           └── api.md          # API-specific rules
│
└── shared/
    └── .claude/rules/
        └── shared-utils.md     # Shared library rules
```

**Monorepo exclusion config:**

```json
// packages/frontend/.claude/settings.local.json
{
  "claudeMdExcludes": [
    "**/backend/CLAUDE.md",
    "**/backend/.claude/rules/**"
  ]
}
```

### 4.4. Cross-Project Rules Sharing

```bash
# Tạo shared rules directory
mkdir -p ~/shared-claude-rules
cat > ~/shared-claude-rules/typescript.md << 'EOF'
# TypeScript Standards
- Always use strict mode
- Prefer type over interface for object types
- Use discriminated unions for state management
EOF

# Symlink vào từng project
cd project-a
ln -s ~/shared-claude-rules .claude/rules/shared

cd project-b
ln -s ~/shared-claude-rules .claude/rules/shared

# Hoặc symlink từng file
ln -s ~/company-standards/security.md .claude/rules/security.md
```

## 5. Cheat Sheet

### 5.1. Commands & Flags

| Command / Flag | Mô tả | Ví dụ |
|---|---|---|
| `/init` | Tạo CLAUDE.md cho project | `/init` |
| `/memory` | View/edit auto memory | `/memory` |
| `/compact` | Compact conversation (giữ CLAUDE.md) | `/compact` |
| `--add-dir` | Load CLAUDE.md từ dir bổ sung | `claude --add-dir ../shared` |

### 5.2. File Locations

| File | Path | Commit vào Git? |
|---|---|---|
| Project CLAUDE.md | `./CLAUDE.md` | ✅ |
| Alt project CLAUDE.md | `./.claude/CLAUDE.md` | ✅ |
| Project rules | `./.claude/rules/*.md` | ✅ |
| Project settings | `./.claude/settings.json` | ✅ |
| Local settings | `./.claude/settings.local.json` | ❌ (gitignore) |
| User CLAUDE.md | `~/.claude/CLAUDE.md` | ❌ (personal) |
| User rules | `~/.claude/rules/*.md` | ❌ (personal) |
| Auto memory | `~/.claude/projects/<proj>/memory/` | ❌ (auto) |
| Managed policy | `/Library/.../ClaudeCode/CLAUDE.md` | ❌ (IT managed) |

### 5.3. CLAUDE.md Syntax

| Syntax | Mô tả | Ví dụ |
|---|---|---|
| `@file` | Import file content | `@README` |
| `@path/to/file.md` | Import specific file | `@docs/standards.md` |
| `@~/path` | Import from home dir | `@~/.claude/my-rules.md` |
| `# Heading` | Section header | `# Code Standards` |
| `- item` | Rule/instruction | `- Use 2-space indent` |

### 5.4. Settings

| Setting | Giá trị | Mô tả |
|---|---|---|
| `autoMemoryEnabled` | `true`/`false` | Bật/tắt auto memory |
| `claudeMdExcludes` | `["glob"]` | Exclude CLAUDE.md files |

### 5.5. Environment Variables

| Variable | Giá trị | Mô tả |
|---|---|---|
| `CLAUDE_CODE_DISABLE_AUTO_MEMORY` | `1` | Tắt auto memory |
| `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD` | `1` | Enable `--add-dir` CLAUDE.md loading |

## 6. Troubleshooting

| # | Lỗi | Nguyên nhân | Fix |
|---|---|---|---|
| 1 | Claude không follow CLAUDE.md | File chưa được load / sai vị trí | Chạy `/memory` verify files loaded. Kiểm tra file nằm đúng vị trí (xem Cheat Sheet 5.2) |
| 2 | Instructions quá chung chung | "Format code properly" quá mơ hồ | Viết cụ thể: "Use 2-space indentation for all TypeScript files" |
| 3 | Xung đột giữa CLAUDE.md files | 2 files chỉ dẫn trái nhau | Review tất cả loaded files, loại bỏ conflicting rules |
| 4 | CLAUDE.md quá lớn (>200 lines) | Một file chứa quá nhiều rules | Split bằng `@imports` hoặc chuyển sang `.claude/rules/` |
| 5 | Instructions mất sau `/compact` | Instructions chỉ nói trong chat | Persist vào CLAUDE.md file — chat instructions không survive compact |
| 6 | Auto memory lưu info sai | Claude hiểu nhầm correction | Chạy `/memory` → review → xóa entry sai |
| 7 | Không biết auto memory lưu gì | Memory hoạt động "ngầm" | Chạy `/memory` để audit. Hoặc đọc trực tiếp `~/.claude/projects/<proj>/memory/` |
| 8 | Rules không apply cho file type | `paths:` pattern sai | Kiểm tra glob pattern. Dùng `**/*.ts` thay vì `*.ts` cho deep matching |
| 9 | Monorepo load nhầm CLAUDE.md | Team khác CLAUDE.md xung đột | Dùng `claudeMdExcludes` trong `.claude/settings.local.json` |
| 10 | `--add-dir` không load CLAUDE.md | Thiếu env var | Set `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` |

### Debugging Checklist

```bash
# 1. Verify loaded files
/memory  # trong Claude Code session

# 2. Check CLAUDE.md exists
ls -la CLAUDE.md .claude/CLAUDE.md .claude/rules/ 2>/dev/null

# 3. Check auto memory storage
ls -la ~/.claude/projects/*/memory/

# 4. Check settings
cat .claude/settings.json 2>/dev/null
cat .claude/settings.local.json 2>/dev/null

# 5. Check excludes
grep -r "claudeMdExcludes" .claude/ 2>/dev/null
```

## 7. Best Practices

### ✅ Gold Rules

| # | Rule | Lý do |
|---|---|---|
| 1 | **Giữ CLAUDE.md dưới 200 dòng** | > 200 dòng giảm instruction adherence |
| 2 | **Viết instructions cụ thể** | "Use 2-space indent" > "Format code nicely" |
| 3 | **Commit CLAUDE.md vào Git** | Team-wide consistency + audit trail |
| 4 | **Dùng `.claude/rules/` cho modular rules** | Tách biệt concerns, path-scoped |
| 5 | **Review auto memory định kỳ** | `/memory` mỗi tuần — xóa entries sai |
| 6 | **Persist quan trọng vào CLAUDE.md** | Đừng chỉ nói trong chat — sẽ mất sau `/compact` |
| 7 | **Gitignore `.claude/settings.local.json`** | Personal settings không nên commit |
| 8 | **Dùng `@imports` cho docs dài** | Giữ CLAUDE.md concise, reference external |
| 9 | **Path-scope rules khi có thể** | Tránh apply rules không liên quan |
| 10 | **Test instructions** | Hỏi Claude "What are the rules for X?" để verify |

### ❌ Anti-Patterns

| # | Anti-Pattern | Hậu quả | Thay thế |
|---|---|---|---|
| 1 | CLAUDE.md > 500 dòng | Claude bỏ sót instructions | Split sang `@imports` + `.claude/rules/` |
| 2 | Instructions mơ hồ | Claude diễn giải tùy ý | Cụ thể, actionable, có ví dụ |
| 3 | Chỉ dùng chat instructions | Mất sau `/compact` hoặc session mới | Ghi vào CLAUDE.md |
| 4 | Không review auto memory | Memory tích tụ noise | `/memory` review hàng tuần |
| 5 | Conflicting rules | Claude chọn arbitrary | Audit cross-file conflicts |
| 6 | Commit `settings.local.json` | Override settings của teammate | Thêm vào `.gitignore` |
| 7 | Quá nhiều rules không path-scoped | Rules frontend apply cho backend | Dùng `paths:` frontmatter |
| 8 | Copy-paste CLAUDE.md giữa projects | Outdated, inconsistent | Symlinks hoặc shared rules directory |

### Chiến lược viết CLAUDE.md hiệu quả

```markdown
# ✅ TỐT — Cụ thể, actionable
- Use 2-space indentation
- Run `npm test` before committing
- API handlers live in `src/api/handlers/`
- Error responses follow format: { error: { code, message } }
- Use `zod` for input validation in API routes

# ❌ XẤU — Mơ hồ, không actionable
- Format code properly
- Test your changes
- Keep files organized
- Handle errors correctly
- Validate inputs
```
