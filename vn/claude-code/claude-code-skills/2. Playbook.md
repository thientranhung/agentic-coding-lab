# Claude Code Skills — Playbook

## Cài đặt & Thiết lập

### Prerequisites

| Yêu cầu | Chi tiết |
|---|---|
| **Claude Code** | Đã cài đặt và hoạt động (terminal, IDE, hoặc desktop) |
| **Folder structure** | `~/.claude/skills/` (user-level) hoặc `.claude/skills/` (project-level) |
| **Shell access** | Cần để chạy `mkdir`, test `!commands` |

### Tạo thư mục Skills

```bash
# User-level (áp dụng cho TẤT CẢ projects)
mkdir -p ~/.claude/skills/

# Project-level (áp dụng cho project hiện tại)
mkdir -p .claude/skills/
```

> [!NOTE]
> User-level skills nằm trong `~/.claude/skills/` — hoạt động ở mọi project. Project-level skills nằm trong `.claude/skills/` — chỉ hoạt động trong project đó và có thể commit vào git.

## Day 1 Workflow — Tạo Skill đầu tiên

### Bước 1: Tạo skill directory

```bash
mkdir -p ~/.claude/skills/explain-code
```

### Bước 2: Viết SKILL.md

```bash
cat > ~/.claude/skills/explain-code/SKILL.md << 'EOF'
---
name: explain-code
description: Explains code with visual diagrams and analogies. Use when explaining how code works, teaching about a codebase, or when the user asks "how does this work?"
---

When explaining code, always include:

1. **Start with an analogy**: Compare the code to something from everyday life
2. **Draw a diagram**: Use ASCII art to show the flow, structure, or relationships
3. **Walk through the code**: Explain step-by-step what happens
4. **Highlight a gotcha**: What's a common mistake or misconception?

Keep explanations conversational. For complex concepts, use multiple analogies.
EOF
```

### Bước 3: Test

Trong Claude Code, thử:

```
How does this code work?
```

Hoặc gọi trực tiếp:

```
/explain-code src/auth/login.ts
```

### Bước 4: Verify skill được discover

```
What skills are available?
```

## Vận hành hàng ngày — Common Tasks

### Tạo skill mới nhanh

```bash
# Tạo structure
SKILL_NAME="deploy"
mkdir -p .claude/skills/$SKILL_NAME

# Viết SKILL.md
cat > .claude/skills/$SKILL_NAME/SKILL.md << 'EOF'
---
name: deploy
description: Deploy the application to production
disable-model-invocation: true
---

Deploy $ARGUMENTS to production:

1. Run the test suite
2. Build the application
3. Push to the deployment target
4. Verify the deployment succeeded
EOF
```

### Chia sẻ skills với team

```bash
# Commit project-level skills
git add .claude/skills/
git commit -m "feat: add team coding skills"
```

### Kiểm tra skills đang active

Trong Claude Code session:

```
What skills are available?
```

Hoặc dùng `/context` để xem context budget.

## Configuration chiến lược — Presets

### Preset 1: Read-only Researcher

Dùng cho skill chỉ đọc code, **không** modify:

```yaml
---
name: deep-research
description: Research a topic thoroughly
context: fork
agent: Explore
allowed-tools: Read, Grep, Glob
---
Research $ARGUMENTS thoroughly:
1. Find relevant files using Glob and Grep
2. Read and analyze the code
3. Summarize findings with specific file references
```

**Khi nào dùng:** Khảo sát codebase mới, tìm hiểu module, audit.

### Preset 2: Protected Action

Dùng cho actions nguy hiểm → chỉ user trigger:

```yaml
---
name: deploy
description: Deploy the application to production
disable-model-invocation: true
---
Deploy $ARGUMENTS to production:
1. Run the test suite
2. Build the application
3. Push to the deployment target
4. Verify the deployment succeeded
```

**Khi nào dùng:** Deploy, commit, send notifications, mutation operations.

### Preset 3: Background Knowledge

Dùng để Claude tự biết mà không cần user trigger:

```yaml
---
name: legacy-system-context
description: Context about the legacy billing system. References when working with billing, payments, or invoice code.
user-invocable: false
---
The legacy billing system uses stored procedures in PostgreSQL.
Key tables: invoices, payments, billing_cycles.
CRITICAL: Never modify the sp_calculate_tax procedure directly.
Always use the wrapper function in src/billing/tax.ts.
```

**Khi nào dùng:** Legacy system knowledge, coding conventions, architectural decisions.

### Preset 4: Dynamic PR Reviewer

Dùng dynamic context injection:

```yaml
---
name: pr-summary
description: Summarize changes in a pull request
context: fork
agent: Explore
allowed-tools: Bash(gh *)
---
## Pull request context
- PR diff: !`gh pr diff`
- PR comments: !`gh pr view --comments`
- Changed files: !`gh pr diff --name-only`

## Your task
Summarize this pull request:
1. What changed and why
2. Potential risks or concerns
3. Suggestions for improvement
```

**Khi nào dùng:** Có `gh` CLI installed, cần review PR nhanh.

### Preset 5: Multi-argument Workflow

```yaml
---
name: migrate-component
description: Migrate a component from one framework to another
argument-hint: "[component] [source-framework] [target-framework]"
disable-model-invocation: true
---
Migrate the $0 component from $1 to $2.
Preserve all existing behavior and tests.

Steps:
1. Read the current $0 implementation in $1
2. Create equivalent in $2
3. Update imports throughout the codebase
4. Run tests to verify
```

**Sử dụng:** `/migrate-component SearchBar React Vue`

### Preset 6: Visual Output with Script

```yaml
---
name: codebase-visualizer
description: Generate an interactive collapsible tree visualization of your codebase
allowed-tools: Bash(python *)
---
# Codebase Visualizer
Run the visualization script from your project root:
```bash
python ${CLAUDE_SKILL_DIR}/scripts/visualize.py .
```

Kèm file `scripts/visualize.py` trong cùng thư mục skill.

**Khi nào dùng:** Cần overview cấu trúc project bằng HTML interactive.

## Cheat Sheet

### Skill Locations

| Scope | Path | Ưu tiên |
|---|---|---|
| User-level | `~/.claude/skills/<name>/SKILL.md` | Thấp nhất |
| Project-level | `.claude/skills/<name>/SKILL.md` | Cao nhất |
| Plugin-level | `<plugin>/skills/<name>/SKILL.md` | Theo plugin |
| Nested (monorepo) | `packages/*/.claude/skills/<name>/SKILL.md` | Auto-discover |
| Additional dir | Via `--add-dir` flag | On-demand |

### Frontmatter Quick Reference

| Field | Ví dụ | Mô tả |
|---|---|---|
| `name` | `deploy` | Tên = `/deploy` command |
| `description` | `"Deploy to production"` | AI matching keywords |
| `disable-model-invocation` | `true` | Chỉ user trigger |
| `user-invocable` | `false` | Chỉ AI trigger |
| `allowed-tools` | `Read, Grep, Glob` | Restrict tools |
| `model` | `haiku` / `sonnet` / `opus` | Override model |
| `context` | `fork` | Chạy trong subagent |
| `agent` | `Explore` / `Plan` / `general-purpose` | Agent type khi fork |
| `argument-hint` | `"[filename] [format]"` | Gợi ý args |
| `hooks` | `{pre_tool_use: ...}` | Lifecycle hooks |

### Arguments Substitution

| Syntax | Input | Result |
|---|---|---|
| `$ARGUMENTS` | `/cmd foo bar` | `"foo bar"` |
| `$ARGUMENTS[0]` | `/cmd foo bar` | `"foo"` |
| `$ARGUMENTS[1]` | `/cmd foo bar` | `"bar"` |
| `$0` | `/cmd foo bar` | `"foo"` |
| `$1` | `/cmd foo bar` | `"bar"` |

### Special Variables

| Variable | Mô tả |
|---|---|
| `${CLAUDE_SESSION_ID}` | Unique ID của session hiện tại |
| `${CLAUDE_SKILL_DIR}` | Absolute path tới thư mục chứa SKILL.md |

### Dynamic Context

| Syntax | Mô tả |
|---|---|
| `!`\``command`\` | Chạy command, inject output vào prompt |
| `!`\``gh pr diff`\` | Inject PR diff |
| `!`\``git log -5`\` | Inject 5 commits gần nhất |

### Permission Rules

| Rule | Hiệu ứng |
|---|---|
| `Skill(commit)` | Allow/deny skill "commit" |
| `Skill(review-pr *)` | Allow/deny "review-pr" + mọi args |
| `Skill(deploy *)` | Allow/deny "deploy" + mọi args |
| `Skill` | Allow/deny TẤT CẢ skills |

### Bundled Skills

| Command | Chức năng |
|---|---|
| `/simplify` | 3-agent parallel code review + auto-fix |
| `/simplify focus on X` | Review tập trung vào X |
| `/batch <instruction>` | Large-scale changes, 1 agent per unit, each in worktree |
| `/debug [description]` | Troubleshoot current session |
| `/loop [interval] <prompt>` | Chạy prompt lặp lại (VD: `/loop 5m check deploy`) |
| `/claude-api` | Load API reference cho ngôn ngữ hiện tại |

## Troubleshooting

### Skill không trigger

| Triệu chứng | Check | Fix |
|---|---|---|
| `/skill-name` không có gì | Skill chưa được discover | Kiểm tra path: `~/.claude/skills/<name>/SKILL.md` |
| Claude không tự trigger | `description` không match | Thêm keywords: "Use when...", "Activate when..." |
| Skill không xuất hiện | Budget hết | Tăng `SLASH_COMMAND_TOOL_CHAR_BUDGET` |
| Trigger nhưng format sai | Instructions chưa rõ | Viết cụ thể hơn, thêm ví dụ output |

### Skill trigger quá nhiều

| Triệu chứng | Check | Fix |
|---|---|---|
| Claude áp dụng skill bất cứ lúc nào | `description` quá generic | Thu hẹp description, thêm điều kiện cụ thể |
| Skill không nên auto-trigger | Thiếu protection | Thêm `disable-model-invocation: true` |

### Lỗi Dynamic Context

| Triệu chứng | Check | Fix |
|---|---|---|
| `!command` không expand | CLI tool chưa cài | Cài tool (VD: `brew install gh`) |
| Output quá lớn | Command trả về quá nhiều | Limit output: `!`\``git log -5`\` thay vì `!`\``git log`\` |
| Command fail silently | Permission denied | Kiểm tra quyền, login lại (VD: `gh auth login`) |

### Lỗi Subagent

| Triệu chứng | Check | Fix |
|---|---|---|
| Subagent không có tool cần thiết | `allowed-tools` quá restrictive | Thêm tools: `Bash, Write, Edit` |
| Subagent mất context | `context: fork` tạo context mới | Inject context qua `!commands` hoặc instructions |
| Subagent quá chậm | Model nặng cho task nhẹ | Đổi `model: haiku` cho tasks đơn giản |

## Best Practices

### Gold Rules ✅

| Rule | Giải thích |
|---|---|
| **1 skill = 1 purpose** | Mỗi skill làm MỘT việc rõ ràng. Không mix deploy + review. |
| **Description là key** | `description` quyết định khi nào Claude trigger. Viết càng cụ thể càng tốt. |
| **Protect dangerous actions** | Luôn thêm `disable-model-invocation: true` cho deploy, commit, delete. |
| **Lazy-load supporting files** | `SKILL.md` giữ concise. Reference files qua relative links. |
| **Test before commit** | Chạy `What skills are available?` và test `/skill-name` trước khi push. |
| **Version control project skills** | `.claude/skills/` nên được commit và review như code. |
| **Use fork for heavy tasks** | Research, batch operations → `context: fork`. Giữ main context sạch. |
| **Argument hints** | Luôn thêm `argument-hint` cho skills có parameters. |

### Anti-patterns ❌

| Anti-pattern | Vấn đề | Thay thế |
|---|---|---|
| **Mega skill** | 1 skill làm 10 việc → triggered sai | Tách thành nhiều skills nhỏ |
| **Generic description** | "Helps with code" → trigger liên tục | "Fix GitHub issue by number" |
| **No invocation control** | Deploy tự trigger | `disable-model-invocation: true` |
| **Huge SKILL.md** | Token budget cạn nhanh | Lazy-load qua relative links |
| **Hardcoded paths** | Không portable | Dùng `${CLAUDE_SKILL_DIR}`, `$ARGUMENTS` |
| **No testing** | Skill không hoạt động | Test với `What skills are available?` |

## Recipes — Tổ hợp nâng cao

### Recipe 1: CI/CD Skill Chain

```bash
# Skill 1: Test → Skill 2: Build → Skill 3: Deploy
# Mỗi skill là 1 step, chain bằng instructions

cat > .claude/skills/ci-pipeline/SKILL.md << 'EOF'
---
name: ci-pipeline
description: Run full CI/CD pipeline
disable-model-invocation: true
context: fork
agent: general-purpose
---
Run the full CI pipeline for $ARGUMENTS:

1. Run tests: `npm test`
2. If tests pass, build: `npm run build`
3. If build succeeds, deploy: `npm run deploy -- $ARGUMENTS`
4. Report back with status of each step
EOF
```

### Recipe 2: Multi-agent Code Review

```bash
cat > .claude/skills/thorough-review/SKILL.md << 'EOF'
---
name: thorough-review
description: Run thorough multi-perspective code review
disable-model-invocation: true
---
Run /simplify on the recently changed files, then:

1. Check for security vulnerabilities
2. Check for performance issues
3. Check for accessibility gaps
4. Summarize all findings in a table

Focus on: $ARGUMENTS
EOF
```

### Recipe 3: Session-aware Logging

```bash
cat > ~/.claude/skills/session-logger/SKILL.md << 'EOF'
---
name: session-logger
description: Log activity for this session
---
Log the following to logs/${CLAUDE_SESSION_ID}.log:
$ARGUMENTS
EOF
```

## Sharing & Distribution

| Method | Cách thực hiện | Best for |
|---|---|---|
| **Project skills** | Commit `.claude/skills/` vào git | Team-specific workflows |
| **User skills** | `~/.claude/skills/` (không commit) | Personal workflows |
| **Plugins** | Tạo plugin với `skills/` directory | Community distribution |
| **Managed settings** | Deploy qua organization settings | Enterprise-wide |

### Tạo Plugin từ Skills

```
my-plugin/
├── .claude-plugin/
│   └── plugin.json          # {"name": "my-plugin", "version": "1.0.0"}
└── skills/
    └── code-review/
        └── SKILL.md          # Skill content
```

Test locally:

```bash
claude --plugin-dir ./my-plugin
```

Skills sẽ available dưới dạng `/my-plugin:code-review`.
