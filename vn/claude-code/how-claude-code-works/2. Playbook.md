# How Claude Code Works — Playbook

## Cài đặt & Thiết lập

### Cài đặt Claude Code

```bash
# macOS / Linux
npm install -g @anthropic-ai/claude-code

# Verify installation
claude --version

# Login
claude /login
```

### Thiết lập dự án mới

```bash
# Di chuyển vào project
cd /path/to/your/project

# Khởi tạo CLAUDE.md — wizard hướng dẫn
claude
# Trong session, gõ:
/init
```

### Cấu hình cơ bản

**1. Project CLAUDE.md** — `./CLAUDE.md` hoặc `./.claude/CLAUDE.md`:

```markdown
# Project Instructions

## Tech Stack
- Node.js 20, TypeScript 5.3
- React 18 with Next.js 14
- PostgreSQL 16

## Conventions
- Use 2-space indentation
- Run `npm test` before committing
- API handlers live in `src/api/handlers/`
- Use `snake_case` for database fields, `camelCase` for TypeScript

## Testing
- Unit tests: `npm test`
- E2E tests: `npm run test:e2e`
- Coverage minimum: 80%
```

**2. Personal CLAUDE.md** — `~/.claude/CLAUDE.md`:

```markdown
# Personal Preferences
- Always explain changes before making them
- Use Vietnamese for comments when possible
- Prefer functional programming patterns
```

**3. Permission Settings** — `.claude/settings.json`:

```json
{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git status)",
      "Bash(git diff *)",
      "Bash(git log *)",
      "Read"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Bash(git push *)"
    ]
  }
}
```

## Day 1 Workflow

### Bước 1: Khởi động lần đầu

```bash
# Mở terminal, vào project
cd ~/my-project

# Chạy Claude Code
claude

# Claude sẽ tự đọc codebase structure
# Gõ /init để tạo CLAUDE.md nếu chưa có
/init
```

### Bước 2: Làm quen với codebase

```
# Trong Claude Code session, hỏi:
Explain the architecture of this project. What are the main modules and how do they interact?

# Claude sẽ tự:
# 1. Đọc file structure
# 2. Đọc README, package.json, config files
# 3. Scan source code
# 4. Trả lời với diagrams/explanations
```

### Bước 3: Task đầu tiên — Bug fix

```
# Cung cấp context cụ thể:
The checkout flow is broken for users with expired cards. 
Check src/payments/ for the issue, especially token refresh. 
Write a failing test first, then fix it.

# Claude sẽ:
# 1. Đọc src/payments/
# 2. Viết failing test
# 3. Fix bug
# 4. Chạy tests để verify
```

### Bước 4: Review và commit

```
# Review changes Claude đã làm
Show me a summary of all changes you made.

# Commit
Commit the changes with a descriptive message.
```

### Bước 5: Đánh giá session

```
# Xem Claude đã học gì
/memory

# Compact conversation nếu dài
/compact focus on the payment fix we just did
```

## Vận hành hàng ngày

### Bắt đầu ngày mới

```bash
# Tiếp tục session hôm qua
claude --continue

# Hoặc chọn session cụ thể
claude --resume

# Hoặc bắt đầu session mới
claude
```

### Pattern làm việc hiệu quả

#### Pattern 1: Explore → Plan → Execute

```
# Bước 1: Explore (Plan mode — Shift+Tab 2 lần)
Read src/auth/ and understand how we handle sessions. 
Then create a plan for adding OAuth support.

# Bước 2: Review plan
# Claude trình bày plan, bạn review

# Bước 3: Execute (chuyển về Default mode)
Go ahead and implement the plan.
```

#### Pattern 2: Test-Driven Development

```
# Viết test trước
Implement validateEmail. 
Test cases: 'user@example.com' → true, 'invalid' → false, '@domain.com' → false. 
Write tests first, then implement, then run tests.
```

#### Pattern 3: Multi-file Refactoring

```
# Delegate cho Claude
Refactor the user module to use the Repository pattern. 
Move database queries from controllers to a new UserRepository class.
Keep all existing tests passing.
```

#### Pattern 4: Code Review

```
# Review PR changes
Review the changes in the current branch compared to main. 
Focus on security issues, performance problems, and code quality.
```

### Sử dụng Sub-agents

```
# Delegate task phức tạp
Run the full test suite in a subagent while we continue working on the API.

# Research trong background
Have a subagent research how to implement WebSocket support 
and write a summary in docs/websocket-plan.md.
```

### CLI Automation

```bash
# One-shot task (không interactive)
claude -p "Write unit tests for src/utils/validator.ts"

# Pipe input
cat error.log | claude -p "Analyze these errors and suggest fixes"

# Batch operations
git diff main --name-only | claude -p "Review these changed files for security issues"

# Monitor logs
tail -f app.log | claude -p "Alert me if you see any anomalies"
```

## Cheat Sheet

### Slash Commands

| Command | Mô tả |
|:---|:---|
| `/init` | Wizard tạo CLAUDE.md cho project |
| `/model` | Đổi model đang dùng |
| `/compact` | Nén context — `/compact focus on X` |
| `/context` | Xem trạng thái context window |
| `/memory` | Xem/edit auto memory |
| `/permissions` | Quản lý permission rules |
| `/mcp` | Xem trạng thái MCP servers |
| `/agents` | Cấu hình subagents |
| `/doctor` | Chẩn đoán lỗi installation |
| `/clear` | Xóa conversation history |
| `/teleport` | Chuyển session từ web → terminal |
| `/desktop` | Chuyển session sang Desktop app |
| `/allowed-tools` | Xem tools được phép |
| `/config` | Xem cấu hình hiện tại |

### CLI Flags

| Flag | Mô tả | Ví dụ |
|:---|:---|:---|
| `--continue` | Tiếp tục session cuối | `claude --continue` |
| `--resume` | Chọn session để tiếp tục | `claude --resume` |
| `--fork-session` | Fork session hiện tại | `claude --continue --fork-session` |
| `--model` | Chỉ định model | `claude --model claude-sonnet-4-6` |
| `-p` | Print mode (one-shot) | `claude -p "fix the bug"` |
| `--add-dir` | Thêm directory context | `claude --add-dir ../shared-lib` |

### Keyboard Shortcuts (trong interactive mode)

| Phím | Hành động |
|:---|:---|
| `Enter` | Gửi message |
| `Esc` | Dừng Claude / Undo changes |
| `Shift+Tab` | Cycle qua permission modes: Default → Auto-accept → Plan |
| `Ctrl+C` | Exit session |

### Permission Rule Quick Reference

| Rule | Ý nghĩa |
|:---|:---|
| `Bash` | Match tất cả bash commands |
| `Bash(npm run *)` | Match `npm run` + bất kỳ subcommand |
| `Bash(git commit *)` | Allow git commits |
| `Read` | Match tất cả file reads |
| `Read(./.env)` | Match đọc file .env cụ thể |
| `Edit` | Match tất cả file edits |
| `WebFetch(domain:*.com)` | Match fetch từ domain pattern |
| `Agent` | Match subagent spawning |

### Environment Variables Quick Reference

| Variable | Mục đích |
|:---|:---|
| `ANTHROPIC_API_KEY` | API key |
| `ANTHROPIC_MODEL` | Override model |
| `CLAUDE_CODE_EFFORT_LEVEL` | `low` / `medium` / `high` |
| `CLAUDE_CODE_DISABLE_AUTO_MEMORY` | Tắt auto memory (`1`) |
| `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` | Ngưỡng autocompact (`50` = 50%) |
| `BASH_DEFAULT_TIMEOUT_MS` | Timeout cho bash |
| `MAX_THINKING_TOKENS` | Giới hạn thinking |

## Troubleshooting

### Lỗi thường gặp

| Lỗi | Nguyên nhân | Fix |
|:---|:---|:---|
| Context window đầy | Session quá dài, quá nhiều files | `/compact`, bắt đầu session mới, hoặc dùng subagents |
| Claude không follow CLAUDE.md | File không load đúng, instructions mơ hồ | Kiểm tra vị trí file, viết cụ thể hơn, dùng `/init` |
| Auto memory lưu thông tin sai | Claude hiểu nhầm pattern | `/memory` → edit/xóa entries sai |
| CLAUDE.md quá lớn | Quá nhiều instructions trong 1 file | Split thành `.claude/rules/` files, dùng `@import` |
| Instructions mất sau `/compact` | Instructions chỉ trong conversation | Đặt vào CLAUDE.md — luôn reload mỗi session |
| Permission bị block | Rules trong settings chặn tool | `/permissions` để review, sửa settings.json |
| Tool bị deny nhưng cần dùng | Deny rule quá rộng | Thêm allow rule cụ thể hơn (allow > deny cho specific) |
| Session cũ không tìm thấy | Session bị cleanup | Tăng `cleanupPeriodDays` trong settings |
| Git conflict khi Claude edit | Nhiều sessions cùng branch | Dùng git worktrees cho parallel sessions |
| Claude chạy lệnh sai | Thiếu context về project | Cập nhật CLAUDE.md với commands đúng |
| MCP server không connect | Config sai hoặc server down | `/mcp` để debug, kiểm tra server process |
| Subagent fail | Task quá phức tạp hoặc context hẹp | Chia nhỏ task, cung cấp context rõ ràng hơn |

## Best Practices

### ✅ Gold Rules

| Rule | Giải thích |
|:---|:---|
| **Be specific upfront** | Cung cấp file paths, test cases, expected behavior ngay từ đầu |
| **Delegate, don't dictate** | Chỉ hướng, để Claude tìm cách — `"Fix the bug in payments"` > `"Open file X, go to line Y, change Z"` |
| **Explore before implementing** | Dùng Plan mode (`Shift+Tab` 2x) cho tasks phức tạp |
| **Viết CLAUDE.md cụ thể** | Actionable instructions, không mơ hồ |
| **Dùng subagents cho tasks song song** | Research, tests, documentation — delegate riêng |
| **`/compact` thường xuyên** | Giữ context clean, focus vào task hiện tại |
| **Review auto memory** | `/memory` định kỳ để đảm bảo Claude học đúng |
| **Git worktrees cho parallel work** | Mỗi worktree = 1 Claude session riêng |
| **Interrupt khi cần** | `Esc` để dừng, điều chỉnh hướng — Claude thích ứng nhanh |
| **Verify with tests** | Luôn yêu cầu chạy tests sau khi thay đổi code |

### ❌ Anti-patterns

| Anti-pattern | Tại sao xấu | Thay thế |
|:---|:---|:---|
| Prompt mơ hồ | Claude phải đoán, tốn tokens | Cung cấp context cụ thể |
| Không dùng CLAUDE.md | Mất context mỗi session | Viết CLAUDE.md cho dự án |
| `dontAsk` mode cho daily work | Mất kiểm soát | Dùng `default` hoặc `acceptEdits` |
| Session quá dài | Context window overflow | Start session mới, dùng `/compact` |
| Dictate từng bước | Không tận dụng agentic capabilities | Delegate outcome, không micromanage |
| Ignore auto memory | Claude có thể lưu sai | Review `/memory` định kỳ |
| Không dùng tests | Không có cách verify | Yêu cầu viết test trước/sau |
| Copy-paste lớn vào prompt | Tốn context | Để Claude tự đọc files |

### Tips nâng cao

**1. Conversation steering:**
```
That's not quite right. The issue is in the session handling, not the auth middleware.
```
→ Redirect Claude mà không cần restart

**2. Incremental complexity:**
```
# Session 1: Basic feature
Add a user profile page with name and email.

# Session 2: Enhance
Add avatar upload to the profile page we created.
```

**3. Structured prompts cho tasks lớn:**
```
I need to add OAuth support. Here's what I'm thinking:
1. Use passport.js
2. Support Google and GitHub providers
3. Store tokens in the existing user table
4. Add login/callback routes

Read the existing auth code in src/auth/ first, then propose any changes to this plan.
```

**4. Automation pipeline:**
```bash
# Daily code quality check
claude -p "Run linter, fix any issues, run tests, and create a summary report in QUALITY.md"

# PR automation
claude -p "Review the diff against main, write a PR description, and commit with a good message"
```
