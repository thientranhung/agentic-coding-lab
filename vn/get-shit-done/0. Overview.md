## 1. GSD là gì?

**GSD (Get Shit Done)** là một hệ thống **meta-prompting**, **context engineering** và **spec-driven development** nhẹ nhưng mạnh mẽ, được thiết kế chuyên dụng cho **Claude Code** và mở rộng hỗ trợ **Gemini CLI**, **OpenCode**, **Codex**, **Copilot CLI**, và **Antigravity**.

Nói đơn giản: GSD là một **lớp điều phối thông minh** nằm giữa bạn và AI, biến Claude Code từ một chatbot viết code thành một **hệ thống kỹ thuật phần mềm** có cấu trúc, có trí nhớ, và có khả năng tự kiểm chứng.

### Vấn đề cốt lõi mà GSD giải quyết

| Vấn đề | Mô tả | Cách GSD giải quyết |
|---|---|---|
| **Context Rot** | Chất lượng phản hồi suy giảm khi context window bị lấp đầy thông tin rác | Mỗi task chạy trong subagent với **200K tokens sạch**; orchestrator chỉ dùng 30-40% context |
| **Vibe-coding** | Lập trình theo cảm hứng → code không nhất quán, vỡ khi mở rộng | Spec-driven development với requirements có traceability |
| **Mất ngữ cảnh** | AI quên quyết định cũ khi đổi phiên làm việc | Hệ thống file trạng thái (`STATE.md`, `PROJECT.md`) + `HANDOFF.json` đóng vai trò "bộ nhớ dài hạn" |
| **Quản lý phức tạp** | Các công cụ quản lý dự án cồng kềnh (Jira, story points...) | "Complexity is in the system, not in your workflow" — người dùng chỉ cần vài lệnh |
| **Thiếu test coverage** | Code ra mà không map được test nào cover requirement nào | Nyquist Validation tự ánh xạ requirements → test commands **trước khi code** |
| **Task failures** | Execution fails → dừng toàn bộ pipeline | Node Repair operator tự RETRY/DECOMPOSE/PRUNE trước khi escalate |

## 2. Triết lý Thiết kế

GSD được xây dựng bởi **TÂCHES** — một lập trình viên solo không viết code trực tiếp mà để Claude Code thực hiện. Triết lý cốt lõi:

> *"Tôi không phải một công ty phần mềm 50 người. Tôi không muốn chơi trò 'enterprise theater'. Tôi chỉ là một người sáng tạo muốn xây dựng những thứ tuyệt vời và hoạt động ổn định."*

### 3 Giá trị Cốt lõi

```mermaid
graph LR
    A["🎯 Reliability<br/>Sự tin cậy"] --> D["GSD"]
    B["⚡ Efficiency<br/>Hiệu suất"] --> D
    C["🧩 Simplicity<br/>Tính đơn giản"] --> D
    D --> E["Sản phẩm<br/>chuyên nghiệp"]
```

1. **Sự tin cậy (Reliability):** Quy trình nghiên cứu domain, plan verification loop (lặp tối đa 3 lần), Nyquist validation, cross-phase regression gates, và node repair đảm bảo code đúng ngay từ đầu.
2. **Hiệu suất (Efficiency):** Sub-agents chuyên biệt chạy song song, mỗi agent có 200K tokens riêng biệt cho từng nhiệm vụ nguyên tử.
3. **Tính đơn giản (Simplicity):** Sự phức tạp được đóng gói bên trong hệ thống. Người dùng chỉ cần tập trung vào tầm nhìn sản phẩm.

## 3. Ai nên dùng GSD?

- **Solo developers** muốn xây dựng sản phẩm chất lượng chuyên nghiệp mà không cần team lớn.
- **Startup founders** cần prototype nhanh nhưng vẫn giữ cấu trúc engineering.
- **Kỹ sư phần mềm** muốn tối ưu workflow AI-assisted development.
- Bất kỳ ai muốn **mô tả ý tưởng** và để hệ thống xây dựng chính xác — không cần giả vờ đang điều hành một tổ chức engineering 50 người.

> **Được tin dùng bởi kỹ sư tại:** Amazon, Google, Shopify, Webflow.

## 4. Kiến trúc Tổng quan

### 4.1. Multi-Runtime Support

GSD hỗ trợ **7 runtime environments**:

| Runtime | Lệnh xác minh | Cơ chế cài đặt | Đặc thù |
|---|---|---|---|
| **Claude Code** | `/gsd:help` | Custom slash commands (`.claude/commands/gsd/`) | Tối ưu sâu, runtime chính |
| **Gemini CLI** | `/gsd:help` | Custom commands (`.gemini/commands/gsd/`) | Hỗ trợ Google Gemini models |
| **OpenCode** | `/gsd-help` | Config-based (`.config/opencode/`) | Mã nguồn mở, `inherit` profile |
| **Codex** | Skills-based | Skills files (`skills/gsd-*/SKILL.md`) + `gsd-autonomous` skill | Vận hành qua skill system |
| **Copilot CLI** | `/gsd:help` | Maps Claude Code tools to GitHub Copilot tools | GitHub Copilot integration |
| **Antigravity** | `/gsd:help` | Full installation support (`--antigravity`) | Google AI runtime |
| **All** | N/A | `--all` flag | Cài cho tất cả runtimes |

### 4.2. Multi-Agent Orchestration

GSD sử dụng mô hình **Orchestrator-Agent**: một orchestrator mỏng (thin orchestrator) sinh ra các agents chuyên biệt, thu thập kết quả, và chuyển tiếp sang bước tiếp theo.

```mermaid
graph TD
    O["🎯 Orchestrator<br/>(30-40% context)"] --> R["🔬 Researchers<br/>(4 agents song song)"]
    O --> P["📋 Planner<br/>(Tạo atomic plans)"]
    O --> PC["✅ Plan Checker<br/>(8 dimensions)"]
    O --> E["⚙️ Executors<br/>(Song song theo waves)"]
    O --> V["🔍 Verifier<br/>(Kiểm chứng codebase)"]
    O --> D["🐛 Debugger<br/>(Chẩn đoán lỗi)"]
    O --> UI["🎨 UI Agents<br/>(Design + Review)"]
    O --> PROF["👤 User Profiler<br/>(8 behavioral dims)"]
    
    R --> |"RESEARCH.md"| P
    P --> |"PLAN.md"| PC
    PC --> |"PASS/FAIL"| P
    PC --> |"Approved Plans"| E
    E --> |"SUMMARY.md"| V
    V --> |"Issues"| D
```

## 5. Context Engineering — Trái tim của GSD

### 5.1. Hệ thống File Trạng thái

GSD sử dụng một bộ tệp Markdown có cấu trúc để duy trì "trí nhớ" xuyên suốt dự án:

| File | Vai trò | Tại sao quan trọng? |
|---|---|---|
| `PROJECT.md` | Tầm nhìn, mục tiêu, quyết định kiến trúc | **Nguồn sự thật duy nhất** — luôn được load |
| `REQUIREMENTS.md` | Yêu cầu v1/v2 với ID truy vết | Tránh scope creep, đảm bảo traceability |
| `ROADMAP.md` | Lộ trình phases + trạng thái | Bản đồ tiến độ toàn cục |
| `STATE.md` | Quyết định đã chốt, blockers, vị trí hiện tại (+ YAML frontmatter) | **Project Memory** — bộ nhớ xuyên phiên |
| `config.json` | Cấu hình workflow, model profile, git strategy | Trung tâm điều khiển |
| `MILESTONES.md` | Lịch sử các milestone đã hoàn thành | Archive và reference |
| `HANDOFF.json` | Machine-readable cross-session continuity (v1.26) | Structured handoff cho automation |
| `WAITING.json` | Signal file cho decision points cần user input (v1.26) | Machine-readable blocked state |
| `research/` | Kiến thức domain từ giai đoạn nghiên cứu | Nền tảng cho planning chính xác |
| `debug/knowledge-base.md` | Persistent debug knowledge (v1.24) | Tránh cold-start cho recurring issues |
| `todos/` | Ý tưởng và tasks phát sinh | Captured ideas for later |

### 5.3. XML Prompt Formatting

Mỗi plan sử dụng cấu trúc XML tối ưu cho Claude:

```xml
<task type="auto">
  <name>Create login endpoint</name>
  <files>src/app/api/auth/login/route.ts</files>
  <action>
    Use jose for JWT (not jsonwebtoken - CommonJS issues).
    Validate credentials against users table.
    Return httpOnly cookie on success.
  </action>
  <verify>curl -X POST localhost:3000/api/auth/login returns 200 + Set-Cookie</verify>
  <done>Valid credentials return cookie, invalid return 401</done>
</task>
```

Mỗi task có: **chỉ dẫn chính xác** → **lệnh kiểm chứng** → **điều kiện hoàn thành**. Không đoán. Không mơ hồ.

## 7. Tính năng Nổi bật

### 7.1. Wave Execution (Thực thi theo Làn sóng)

Plans được nhóm thành "waves" dựa trên dependencies:
- **Wave 1:** Các plans độc lập → chạy **song song**
- **Wave 2:** Plans phụ thuộc Wave 1 → chạy sau khi Wave 1 xong
- **Vertical Slices** được ưu tiên hơn Horizontal Layers → song song hóa tốt hơn
- **Pre-wave dependency checks** + cross-plan data contracts (v1.26)

### 7.2. Atomic Git Commits

Mỗi task nhỏ = 1 commit riêng biệt. Cho phép `git bisect` tìm chính xác task gây lỗi.

### 7.3. Nyquist Validation (v1.21+)

Hệ thống ánh xạ test coverage tới requirements **trước khi viết code**:
- Researcher phát hiện test infrastructure hiện có
- Plan checker enforce 8th verification dimension: mỗi task phải có `verify` command
- Requirements coverage gate: plan-phase verify tất cả phase requirements covered (v1.26)
- Retroactive audit qua `/gsd:validate-phase`

### 7.4. Node Repair Operator (v1.23+)

Khi task verification fail, GSD tự recovery trước khi escalate:
- **RETRY** — thử lại task
- **DECOMPOSE** — chia task nhỏ hơn
- **PRUNE** — bỏ task không cần thiết
- Budget: `workflow.node_repair_budget` (default: 2 attempts)
- Disable: `workflow.node_repair: false`

### 7.5. UI Design System (v1.23+)

| Lệnh | Vai trò | Agent |
|---|---|---|
| `/gsd:ui-phase [N]` | Generate UI design contract cho frontend phases | `gsd-ui-researcher` + `gsd-ui-checker` |
| `/gsd:ui-review [N]` | Retroactive 6-pillar visual audit | `gsd-ui-auditor` |

**6 Audit Pillars** (scored 1-4): Copywriting, Visuals, Color, Typography, Spacing, Experience Design.

### 7.6. Developer Profiling (v1.26)

`/gsd:profile-user` phân tích Claude Code session history → build behavioral profile:
- **8 dimensions:** communication style, decision patterns, debugging approach, UX preferences, vendor choices, frustration triggers, learning style, explanation depth
- **Output:** `USER-PROFILE.md`, `/gsd:dev-preferences` command, `CLAUDE.md` profile section
- Fallback: `--questionnaire` mode nếu không có session history
- Refresh: `--refresh` để re-analyze

### 7.7. PR Automation — `/gsd:ship` (v1.26)

Tạo PR từ verified phase work:
- Auto-generate rich PR body từ planning artifacts (goal, changes, REQ-IDs, verification status, key decisions)
- Push branch + create PR via `gh` CLI
- Update STATE.md
- `--draft` flag cho draft PRs

### 7.8. Quick Mode (Enhanced v1.24)

`/gsd:quick` cho các tác vụ ad-hoc với flags composable:

| Flag | Tác dụng |
|---|---|
| `--discuss` | Pre-planning discussion (v1.22.4) |
| `--research` | Spawn focused researcher trước planning (v1.24) |
| `--full` | Plan checking (2 iterations) + post-execution verification |
| (composable) | `--discuss --research --full` cho maximum quality |

### 7.9. Autonomous Mode

`/gsd:autonomous` chạy tất cả remaining phases tự động. `--from N` để bắt đầu từ phase cụ thể.

### 7.10. Git Branching Strategies (v1.22+)

| Strategy | Mô tả | Best For |
|---|---|---|
| `none` | Commit trực tiếp branch hiện tại | Solo, simple |
| `phase` | Branch per phase, merge khi hoàn thành | Code review per phase |
| `milestone` | Branch per milestone, merge khi hoàn thành | Release branches |

### 7.11. Cross-Phase Regression Gate (v1.26)

Execute-phase chạy **prior phases' test suites** sau execution, bắt regressions trước khi chúng compound. Requirements coverage gate ở plan-phase đảm bảo tất cả phase requirements được cover.

### 7.12. MCP Tool Awareness (v1.26)

GSD subagents có thể discover và sử dụng **MCP server tools**, bao gồm Context7 cho library documentation.

## 8. So sánh: Vibe-coding vs GSD Engineering

| Đặc điểm | Vibe-coding | GSD Engineering |
|---|---|---|
| **Context** | Tích tụ → suy giảm chất lượng | Fresh 200K per task |
| **Thực thi** | Chat-and-fix rời rạc | Atomic plans → parallel waves |
| **Git** | 1 commit lớn | Atomic commits per task |
| **Kiểm chứng** | "Chạy thử xem" | Automated + Manual UAT + Regression gate |
| **Trí nhớ** | Mất khi đổi phiên | STATE.md + HANDOFF.json + resume-work |
| **Mở rộng** | Vỡ khi phức tạp | Multi-agent orchestration |
| **Task failure** | Dừng → manual fix | Node repair: RETRY/DECOMPOSE/PRUNE |
| **UI Quality** | Chủ quan | 6-pillar quantitative audit |
