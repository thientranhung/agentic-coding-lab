## Phần I: Cài đặt & Thiết lập Môi trường

### 1.1. Cài đặt Nhanh (30 giây)

```bash
npx get-shit-done-cc@latest
```

Installer sẽ hỏi bạn 2 câu:
1. **Runtime:** Claude Code, OpenCode, Gemini, Codex, Copilot, Antigravity, hoặc All
2. **Location:** Global (tất cả dự án) hoặc Local (dự án hiện tại)

**Xác minh cài đặt thành công:**

| Runtime | Lệnh kiểm tra |
|---|---|
| Claude Code | `/gsd:help` |
| Gemini CLI | `/gsd:help` |
| OpenCode | `/gsd-help` |
| Codex | `$gsd-help` |
| Copilot CLI | `/gsd:help` |
| Antigravity | `/gsd:help` |


### 1.3. Cập nhật

```bash
npx get-shit-done-cc@latest
```

Từ v1.17+, installer tự backup local modifications vào `gsd-local-patches/`. Dùng `/gsd:reapply-patches` để restore lại.

> [!TIP]
> `/gsd:update` là cách cập nhật từ trong session — nó sẽ shows changelog preview và targets đúng runtime directory.

### 1.4. Chế độ Skip Permissions (Khuyến nghị)

```bash
claude --dangerously-skip-permissions
```

> [!TIP]
> GSD được thiết kế cho automation liên tục. Dừng lại phê duyệt `date` và `git commit` 50 lần mỗi phiên sẽ phá vỡ "flow" và giảm hiệu suất đáng kể.

**Alternative — Granular Permissions:**

```json
{
  "permissions": {
    "allow": [
      "Bash(date:*)", "Bash(echo:*)", "Bash(cat:*)", "Bash(ls:*)",
      "Bash(mkdir:*)", "Bash(wc:*)", "Bash(head:*)", "Bash(tail:*)",
      "Bash(sort:*)", "Bash(grep:*)", "Bash(tr:*)",
      "Bash(git add:*)", "Bash(git commit:*)", "Bash(git status:*)",
      "Bash(git log:*)", "Bash(git diff:*)", "Bash(git tag:*)"
    ]
  }
}
```

### 1.5. Bảo mật — Cấu hình Deny List

> [!CAUTION]
> **Bắt buộc** cấu hình trước khi dùng GSD với bất kỳ dự án nào có chứa secrets.

Thêm vào `.claude/settings.json`:

```json
{
  "permissions": {
    "deny": [
      "Read(.env)", "Read(.env.*)",
      "Read(**/secrets/*)", "Read(**/*credential*)",
      "Read(**/*.pem)", "Read(**/*.key)"
    ]
  }
}
```

### 1.6. Docker/Container/WSL Environments

```bash
# Docker — tràn tilde paths
CLAUDE_CONFIG_DIR=/home/youruser/.claude npx get-shit-done-cc --global

# WSL — GSD sẽ detect WSL + Windows Node.js mismatch và warn
```

## Phần II: Day 1 — Dự án Mới (Greenfield)

### 2.1. Quy trình Đầy đủ từ A→Z

```bash
# Bước 0: Khởi chạy Claude Code
claude --dangerously-skip-permissions

# Bước 1: Khởi tạo dự án (Q&A → Research → Requirements → Roadmap)
/gsd:new-project

# Bước 2: Clear context, bắt đầu phase loop
/clear

# Bước 3-7: Loop cho mỗi phase
/gsd:discuss-phase 1        # Lock in preferences
/gsd:ui-phase 1             # UI design contract (frontend phases)
/gsd:plan-phase 1           # Research + Plan + Verify
/gsd:execute-phase 1        # Parallel wave execution + regression gate
/gsd:verify-work 1          # Manual UAT
/gsd:ui-review 1            # Visual audit (frontend phases)
/clear

# Lặp lại cho phase 2, 3, ...

# Khi tất cả phases hoàn tất
/gsd:audit-milestone         # Kiểm tra DoD
/gsd:ship                    # Create PR từ planning artifacts
/gsd:complete-milestone      # Archive + Tag release
```

### 2.2. Quick Flow — `/gsd:next` (NEW v1.26)

Không nhớ next step? Chỉ cần:

```bash
/gsd:next                    # Auto-advance to next logical step
```

### 2.3. Khởi tạo từ Document Sẵn có

```bash
/gsd:new-project --auto @prd.md
```

Hệ thống tự động chạy research → requirements → roadmap từ document. Tiếp tục workflow bình thường từ discuss-phase.

### 2.4. Autonomous Mode

Muốn chạy toàn bộ remaining phases tự động:

```bash

/gsd:autonomous --from 3       # Bắt đầu từ phase 3
```

## Phần IV: Vận hành Hàng ngày — Phase Loop

### 4.1. Discuss Phase — "Shape the Build"

```bash
/gsd:discuss-phase 1
/gsd:discuss-phase 3 --auto    # Auto-select defaults
/gsd:discuss-phase --batch     # Grouped question intake (v1.23)
```

**Code-aware discuss (v1.22):** GSD analyze relevant source files trước khi hỏi — không hỏi lại điều đã rõ trong code.

### 4.2. UI Design Phase (NEW v1.23)

```bash
/gsd:ui-phase 2                # Generate UI design contract
```

- Detect design system state (shadcn, Tailwind config, existing tokens)
- Auto-offer shadcn initialization cho React/Next.js/Vite
- Registry safety gate cho third-party components
- Validation loop (max 2 iterations): BLOCK/FLAG/PASS

### 4.3. Plan Phase — "Blueprint the Build"

```bash
/gsd:plan-phase 1
/gsd:plan-phase 3 --skip-research    # Skip research
/gsd:plan-phase --skip-verify        # Skip plan checker
/gsd:plan-phase --auto               # Non-interactive
```

**v1.25:** Plan-phase asks user about research thay vì silently deciding.

**Trước khi plan — xem AI dự định gì:**

```bash
/gsd:list-phase-assumptions 1
```

### 4.4. Execute Phase — "Build It"

```bash
/gsd:execute-phase 1
```

**v1.23+:** Node repair operator tự RETRY/DECOMPOSE/PRUNE khi task verification fail.

**v1.26:** Cross-phase regression gate — chạy prior phases' test suites sau execution.

**v1.26:** Interactive executor mode cho pair-programming style execution.

### 4.5. Verify Work — "Test It"

```bash
/gsd:verify-work 1
```

- Cold-start smoke test auto-inject cho phases sửa server/database/seed/startup files (v1.22.3)
- Debug agents tự chẩn đoán root cause + tạo fix plans
- Debug sessions save to persistent knowledge base (v1.24)

### 4.6. UI Review (NEW v1.23)

```bash
/gsd:ui-review 1               # 6-pillar visual audit
```

6 Pillars (scored 1-4): Copywriting, Visuals, Color, Typography, Spacing, Experience Design.

### 4.7. Ship (NEW v1.26)

```bash
/gsd:ship 4                    # Ship phase 4 as PR
/gsd:ship 4 --draft            # Draft PR
```

## Phần IX: Configuration Chiến lược

### 9.1. Model Profiles

```bash
/gsd:set-profile quality       # Max quality, Opus heavy
/gsd:set-profile balanced      # Default - Opus for planning only
/gsd:set-profile budget        # Cost-effective - Sonnet/Haiku

```

**v1.24:** `/gsd:set-profile` chạy dưới dạng script programmatic — xong trong seconds thay vì 30-40s LLM-driven.

### 9.2. Workflow Presets

| Scenario | mode | granularity | profile | research | plan_check | verifier | ui_phase | node_repair |
|---|---|---|---|---|---|---|---|---|
| Prototyping | yolo | coarse | budget | off | off | off | off | off |
| Normal dev | interactive | standard | balanced | on | on | on | on | on |
| Production | interactive | fine | quality | on | on | on | on | on |

### 9.3. Context Window Control (v1.25)

Disable context monitor warnings:

```json
// .planning/config.json
{ "hooks": { "context_warnings": false } }
```

## Phần X: Troubleshooting

### 10.1. Lệnh không tìm thấy

- **Restart runtime** để reload commands/skills
- **Verify files:**
  - Claude: `~/.claude/commands/gsd/` (global) hoặc `./.claude/commands/gsd/` (local)
  - Codex: `~/.codex/skills/gsd-*/SKILL.md`
  - OpenCode: `.config/opencode/` config
  - Copilot: Maps to GitHub Copilot tools
  - Antigravity: Agent Skills format
- **Reinstall:** `npx get-shit-done-cc@latest`

### 10.2. "Project already initialized"

`.planning/PROJECT.md` đã tồn tại. Nếu muốn bắt đầu lại: xóa thư mục `.planning/`.

### 10.3. Chất lượng AI suy giảm

```bash
/clear                         # Clear context window
/gsd:resume-work               # Restore state từ files
```

### 10.4. Plans sai hướng

```bash
/gsd:list-phase-assumptions 1  # Xem Claude dự định gì
/gsd:discuss-phase 1           # Sửa hướng bằng preferences
/gsd:plan-phase 1              # Re-plan
```

### 10.5. Execution tạo stubs/code không đầy đủ

- Plans quá lớn → chia nhỏ hơn (2-3 tasks/plan max)
- Check `read_first` section có đủ context không (v1.23+)

### 10.6. Node repair exhausted budget

- Tăng `workflow.node_repair_budget` trong config.json
- Hoặc fix manually → re-execute

### 10.7. Agent suggests non-existent commands

Fixed v1.26: Agent không còn suggest `/gsd:transition` (không tồn tại). Nếu vẫn gặp, chạy `/gsd:update`.

### 10.8. Chi phí quá cao

```bash
/gsd:set-profile budget        # Switch to Sonnet/Haiku
/gsd:settings                  # Tắt research, plan_check, verifier
```

### 10.9. Windows-specific Issues

- `@file:` protocol resolution cho large payloads (>50KB) — fixed v1.22.4
- EPERM/EACCES khi scanning protected directories — fixed v1.24
- WSL + Windows Node.js mismatch → GSD sẽ detect và warn (v1.23)
- CRLF frontmatter parsing — fixed v1.26

### 10.10. Uninstall

```bash
npx get-shit-done-cc --claude --global --uninstall
npx get-shit-done-cc --opencode --global --uninstall
npx get-shit-done-cc --codex --global --uninstall
npx get-shit-done-cc --copilot --global --uninstall
npx get-shit-done-cc --antigravity --global --uninstall
```

## Phần XI: Best Practices từ Thực chiến

### 11.1. Gold Rules — 9 Quy tắc Vàng

1. **`/clear` giữa phases.** Context window sạch = chất lượng đỉnh.
2. **Đầu tư thời gian cho Discuss.** Bạn càng rõ ràng, AI càng chính xác.
3. **Vertical Slices > Horizontal Layers.** Chia feature E2E, đừng chia theo layer.
4. **Dùng `/gsd:progress` hoặc `/gsd:next` thường xuyên.** Đây là la bàn của bạn.
5. **Không manual debug.** Dùng `/gsd:verify-work` hoặc `/gsd:debug` để AI tự chẩn đoán.
6. **Commit docs ban đầu.** `commit_docs: true` để team members và future-you hiểu context.
7. **Cấu hình deny list TRƯỚC khi bắt đầu.** Defense-in-depth cho secrets.
8. **Dùng `/gsd:ui-phase` cho frontend.** UI design contract tránh "vibe-design".
9. **Dùng `/gsd:note` khi có ý tưởng.** Capture ideas ngay, promote later.

### 11.2. Anti-Patterns — Tránh làm gì

| ❌ Anti-Pattern | ✅ Best Practice |
|---|---|
| Chấp nhận defaults qua Discuss quá nhanh | Trả lời chi tiết, mô tả vision cá nhân |
| Không `/clear` giữa phases | Clear context sau mỗi verify |
| Manual debug khi verify fail | Để GSD spawn debug agents |
| Plans quá lớn (5+ tasks) | Giữ 2-3 tasks/plan, dùng `fine` granularity |
| Bỏ qua audit trước complete | LUÔN audit → plan gaps → complete |
| Skip `/gsd:ui-phase` cho frontend | UI-SPEC tạo design contract, giảm revision |
| Không dùng `/gsd:note` | Ideas mất khi context cleared |
