## Phần I: Cài đặt & Thiết lập Môi trường

### 1.1. Cài đặt Nhanh (30 giây)

```bash
npx get-shit-done-cc@latest
```

Installer sẽ hỏi bạn 2 câu:
1. **Runtime:** Claude Code, OpenCode, Gemini, Codex, hoặc All
2. **Location:** Global (tất cả dự án) hoặc Local (dự án hiện tại)

**Xác minh cài đặt thành công:**

| Runtime | Lệnh kiểm tra |
|---|---|
| Claude Code | `/gsd:help` |
| Gemini CLI | `/gsd:help` |
| OpenCode | `/gsd-help` |
| Codex | `$gsd-help` |

### 1.2. Cài đặt Non-Interactive (Docker, CI, Scripts)

```bash
# Claude Code
npx get-shit-done-cc --claude --global   # → ~/.claude/
npx get-shit-done-cc --claude --local    # → ./.claude/

# Gemini CLI
npx get-shit-done-cc --gemini --global   # → ~/.gemini/

# OpenCode
npx get-shit-done-cc --opencode --global # → ~/.config/opencode/

# Codex
npx get-shit-done-cc --codex --global    # → ~/.codex/

# Tất cả
npx get-shit-done-cc --all --global
```

### 1.3. Cập nhật

```bash
npx get-shit-done-cc@latest
```

Từ v1.17+, installer tự backup local modifications vào `gsd-local-patches/`. Dùng `/gsd:reapply-patches` để restore lại.

### 1.4. Chế độ Skip Permissions (Khuyến nghị)

```bash
claude --dangerously-skip-permissions
```

> [!TIP]
> GSD được thiết kế cho automation liên tục. Dừng lại phê duyệt `date` và `git commit` 50 lần mỗi phiên sẽ phá vỡ "flow" và giảm hiệu suất đáng kể.

**Alternative — Granular Permissions:**

```json
{
  "permissions": {
    "allow": [
      "Bash(date:*)", "Bash(echo:*)", "Bash(cat:*)", "Bash(ls:*)",
      "Bash(mkdir:*)", "Bash(wc:*)", "Bash(head:*)", "Bash(tail:*)",
      "Bash(sort:*)", "Bash(grep:*)", "Bash(tr:*)",
      "Bash(git add:*)", "Bash(git commit:*)", "Bash(git status:*)",
      "Bash(git log:*)", "Bash(git diff:*)", "Bash(git tag:*)"
    ]
  }
}
```

### 1.5. Bảo mật — Cấu hình Deny List

> [!CAUTION]
> **Bắt buộc** cấu hình trước khi dùng GSD với bất kỳ dự án nào có chứa secrets.

Thêm vào `.claude/settings.json`:

```json
{
  "permissions": {
    "deny": [
      "Read(.env)",
      "Read(.env.*)",
      "Read(**/secrets/*)",
      "Read(**/*credential*)",
      "Read(**/*.pem)",
      "Read(**/*.key)"
    ]
  }
}
```

### 1.6. Docker/Container Environments

Nếu gặp lỗi đường dẫn tilde (`~`):

```bash
CLAUDE_CONFIG_DIR=/home/youruser/.claude npx get-shit-done-cc --global
```

## Phần II: Day 1 — Dự án Mới (Greenfield)

### 2.1. Quy trình Đầy đủ từ A→Z

```bash
# Bước 0: Khởi chạy Claude Code
claude --dangerously-skip-permissions

# Bước 1: Khởi tạo dự án (Q&A → Research → Requirements → Roadmap)
/gsd:new-project

# Bước 2: Clear context, bắt đầu phase loop
/clear

# Bước 3-6: Loop cho mỗi phase
/gsd:discuss-phase 1        # Lock in preferences
/gsd:plan-phase 1           # Research + Plan + Verify
/gsd:execute-phase 1        # Parallel wave execution
/gsd:verify-work 1          # Manual UAT
/clear

# Lặp lại cho phase 2, 3, ...
/gsd:discuss-phase 2
/gsd:plan-phase 2
/gsd:execute-phase 2
/gsd:verify-work 2
/clear

# Khi tất cả phases hoàn tất
/gsd:audit-milestone         # Kiểm tra DoD
/gsd:complete-milestone      # Archive + Tag release
```

### 2.2. Khởi tạo từ Document Sẵn có

Nếu bạn đã có PRD hoặc idea doc:

```bash
/gsd:new-project --auto @prd.md
```

Hệ thống tự động chạy research → requirements → roadmap từ document. Tiếp tục workflow bình thường từ discuss-phase.

### 2.3. Mẹo cho `/gsd:new-project`

> [!IMPORTANT]
> **Đầu tư thời gian cho Q&A.** Đây là bước quan trọng nhất.
> - Trả lời chi tiết, đừng chấp nhận defaults vội vàng.
> - Nêu rõ edge cases, ràng buộc kỹ thuật, preferences.
> - Mô tả rõ MVP (v1) so với v2.
> - AI sẽ hỏi cho đến khi hiểu 100%.

## Phần III: Day 1 — Dự án Hiện có (Brownfield)

### 3.1. Map Codebase Trước

```bash
# Bước 0: Phân tích codebase (4 mapper agents song song)
/gsd:map-codebase

# Output:
# codebase/STACK.md          → Tech stack, dependencies
# codebase/ARCHITECTURE.md   → Code structure, patterns
# codebase/CONVENTIONS.md    → Naming, style, practices
# codebase/CONCERNS.md       → Tech debt, security, risks

# Bước 1: Khởi tạo (questions focus on NEW features)
/gsd:new-project
# (workflow bình thường từ đây)
```

### 3.2. Tại sao phải Map trước?

- AI **hiểu code hiện tại** → không hỏi lại điều đã rõ trong code
- Plans **tuân thủ conventions** đã phát hiện tự động
- Tránh tạo **"broken windows"** trong kiến trúc cũ

## Phần IV: Vận hành Hàng ngày — Phase Loop

### 4.1. Discuss Phase — "Shape the Build"

```bash
/gsd:discuss-phase 1
```

**Khi nào dùng:** Trước mỗi planning. **LUÔN LUÔN** dùng nếu bạn có ý tưởng cụ thể.

**Hệ thống phân tích và hỏi dựa trên loại feature:**

| Loại Feature | Gray Areas AI sẽ hỏi |
|---|---|
| **Visual (UI)** | Layout, density, interactions, empty states, responsive behavior |
| **APIs/CLIs** | Response format, flags, error handling, verbosity, authentication |
| **Content** | Structure, tone, depth, flow, localization |
| **Organization** | Grouping criteria, naming conventions, duplicates, exceptions |

**Pro-tip:**
- **Sâu = chính xác.** Bạn càng trả lời chi tiết, AI càng xây đúng ý bạn.
- **Nông = defaults.** Bỏ qua discuss = nhận sản phẩm generic.
- **Output:** `{N}-CONTEXT.md` — file này điều hướng toàn bộ research + planning.

### 4.2. Plan Phase — "Blueprint the Build"

```bash
/gsd:plan-phase 1
```

**Khi nào dùng:** Sau discuss, trước execute.

**Quy trình 3 bước tự động:**
1. **Research** — 4 researchers song song (stack, features, architecture, pitfalls)
2. **Plan** — Tạo 2-3 atomic plans với XML structure
3. **Verify** — Plan checker kiểm tra 8 dimensions, loop tối đa 3 lần

**Flags hữu ích:**

| Flag | Tác dụng |
|---|---|
| `--skip-research` | Bỏ qua research (domain quen thuộc) |
| `--skip-verify` | Bỏ qua plan checker (quick iterations) |

**Trước khi plan — xem AI dự định gì:**

```bash
/gsd:list-phase-assumptions 1
```

Lệnh này cho bạn thấy Claude dự định tiếp cận phase như thế nào, trước khi commit vào plan. Nếu hướng sai → chỉnh bằng discuss.

### 4.3. Execute Phase — "Build It"

```bash
/gsd:execute-phase 1
```

**Khi nào dùng:** Sau khi plans được approved.

**Cơ chế:**
- Plans chạy theo **waves** (song song khi independent, tuần tự khi dependent)
- Mỗi executor nhận **200K tokens sạch** + PROJECT.md + plan
- **Atomic commit** ngay khi mỗi task hoàn thành
- Auto-verify khi tất cả plans chạy xong

> [!TIP]
> **Walk away.** Đây là lúc bạn có thể đi pha cà phê. Quay lại, kiểm tra git log.

### 4.4. Verify Work — "Test It"

```bash
/gsd:verify-work 1
```

**Khi nào dùng:** Sau execute, trước khi chuyển phase tiếp theo.

**Quy trình UAT có hướng dẫn:**
1. Hệ thống liệt kê **deliverables có thể test**
2. Hướng dẫn bạn test **từng cái một**: "Bạn có thể login bằng email không?"
3. Bạn trả lời: ✅ Yes / ❌ No + mô tả lỗi

**Nếu có lỗi:**
- Debug agents tự động chẩn đoán root cause
- Tạo fix plans cụ thể
- Chạy lại `/gsd:execute-phase 1` → fix plans được áp dụng
- **Bạn KHÔNG cần manual debug**

### 4.5. Context Management giữa các Phases

> [!IMPORTANT]
> `/clear` giữa các phases là **best practice**. GSD thiết kế xung quanh fresh contexts.

```bash
/gsd:execute-phase 1
/gsd:verify-work 1
/clear                    # ← Clear context trước phase mới
/gsd:discuss-phase 2
```

## Phần V: Milestone Management

### 5.1. Audit Milestone

```bash
/gsd:audit-milestone
```

Kiểm tra milestone đã đạt **Definition of Done** chưa:
- Tất cả requirements đã implemented?
- Có stubs/placeholder code không?
- Tests coverage đạt yêu cầu?

### 5.2. Complete Milestone

```bash
/gsd:complete-milestone
```

- Archive milestone documents
- Tag release trên git
- Dọn dẹp trạng thái cho milestone tiếp theo

### 5.3. Bắt đầu Milestone Mới

```bash
/gsd:new-milestone [name]
```

Giống `/gsd:new-project` nhưng cho codebase đã có:
- Mô tả mục tiêu milestone mới
- Research domain cho features mới
- Scope requirements mới
- Tạo roadmap mới

### 5.4. Xử lý Gaps sau Audit

```bash
/gsd:audit-milestone           # Phát hiện gaps
/gsd:plan-milestone-gaps       # Tạo phases để close gaps
# (normal phase workflow)
/gsd:complete-milestone        # Archive khi done
```

## Phần VII: Quick Mode — Tác vụ Ad-hoc

### 7.1. Quick Task

```bash
/gsd:quick
> "Fix login button not responding on mobile Safari"
```

- **Same quality agents** (planner + executor)
- **Skip:** Research, plan checker, verifier
- **Separate tracking:** `.planning/quick/001-fix-login-button/`
- **Use for:** Bug fixes, small features, config changes

### 7.2. Quick với Full Checks

```bash
/gsd:quick --full              # Adds plan-checking + verification
```

### 7.3. Quick với Discussion

```bash
/gsd:quick --discuss           # Pre-planning discussion trước khi execute
```

## Phần VIII: Session Management

### 8.1. Tạm dừng Giữa chừng

```bash
/gsd:pause-work                # Tạo handoff note
```

### 8.2. Quay lại làm việc

```bash
/gsd:resume-work               # Full context restoration
# hoặc
```


- Root cause analysis
- Fix plan generation

## Phần IX: Configuration Chiến lược

### 9.1. Chuyển đổi Model Profile

```bash
/gsd:set-profile quality       # Max quality, Opus heavy
/gsd:set-profile balanced      # Default - Opus for planning only
/gsd:set-profile budget        # Cost-effective - Sonnet/Haiku
```

### 9.2. Cấu hình Tổng hợp qua Settings

```bash
/gsd:settings                  # Interactive config
```

### 9.3. Git Branching

Trong `/gsd:settings` hoặc trực tiếp `config.json`:

| Strategy | Khi nào dùng | Branch name template |
|---|---|---|
| `none` | Solo dev, simple projects | N/A |
| `phase` | Code review per phase | `gsd/phase-{phase}-{slug}` |
| `milestone` | Release branches | `gsd/{milestone}-{slug}` |

### 9.4. Workflow Presets theo Scenario

```bash
# Prototyping nhanh - tốc độ > chất lượng
/gsd:settings
→ mode: yolo, granularity: coarse, profile: budget
→ research: off, plan_check: off, verifier: off

# Development bình thường
/gsd:settings
→ mode: interactive, granularity: standard, profile: balanced
→ research: on, plan_check: on, verifier: on

# Production code - chất lượng > tốc độ
/gsd:settings
→ mode: interactive, granularity: fine, profile: quality
→ research: on, plan_check: on, verifier: on
```

## Phần XI: Troubleshooting

### 11.1. Lệnh không tìm thấy

- **Restart runtime** để reload commands/skills
- **Verify files:**
  - Claude: `~/.claude/commands/gsd/` (global) hoặc `./.claude/commands/gsd/` (local)
  - Codex: `~/.codex/skills/gsd-*/SKILL.md`
- **Reinstall:** `npx get-shit-done-cc@latest`

### 11.2. "Project already initialized"

`.planning/PROJECT.md` đã tồn tại. Nếu muốn bắt đầu lại: xóa thư mục `.planning/`.

### 11.3. Chất lượng AI suy giảm (Context Degradation)

```bash
/clear                         # Clear context window
/gsd:resume-work               # Restore state từ files
```

### 11.4. Plans sai hướng

```bash
/gsd:list-phase-assumptions 1  # Xem Claude dự định gì
/gsd:discuss-phase 1           # Sửa hướng bằng preferences
/gsd:plan-phase 1              # Re-plan
```

### 11.5. Execution tạo stubs/code không đầy đủ

- Plans quá lớn → chia nhỏ hơn (2-3 tasks/plan max)
- Re-plan với scope nhỏ hơn

### 11.6. Chi phí quá cao

```bash
/gsd:set-profile budget        # Switch to Sonnet/Haiku
/gsd:settings                  # Tắt research, plan_check, verifier
```

### 11.7. Subagent báo fail nhưng code đã viết

Kiểm tra `git log` — GSD's orchestrators spot-check output. Nếu commits tồn tại → công việc thực sự đã hoàn thành.

### 11.8. Uninstall

```bash
# Global
npx get-shit-done-cc --claude --global --uninstall
npx get-shit-done-cc --opencode --global --uninstall
npx get-shit-done-cc --codex --global --uninstall

# Local
npx get-shit-done-cc --claude --local --uninstall
npx get-shit-done-cc --opencode --local --uninstall
npx get-shit-done-cc --codex --local --uninstall
```

## Phần XII: Best Practices từ Thực chiến

### 12.1. Gold Rules — 7 Quy tắc Vàng

1. **`/clear` giữa phases.** Context window sạch = chất lượng đỉnh.
2. **Đầu tư thời gian cho Discuss.** Bạn càng rõ ràng, AI càng chính xác.
3. **Vertical Slices > Horizontal Layers.** Chia feature E2E, đừng chia theo layer.
4. **Dùng `/gsd:progress` thường xuyên.** Đây là la bàn của bạn.
5. **Không manual debug.** Dùng `/gsd:verify-work` hoặc `/gsd:debug` để AI tự chẩn đoán.
6. **Commit docs ban đầu.** `commit_docs: true` để team members và future-you hiểu context.
7. **Cấu hình deny list TRƯỚC khi bắt đầu.** Defense-in-depth cho secrets.

### 12.2. Git Workflow Tips

- **Atomic commits** cho phép `git bisect` tìm exact failing task
- **Branch per phase** khi cần code review
- **Squash merge milestones** cho clean main branch

### 12.3. Khi nào dùng Quick vs Full Workflow?

| Scenario | Dùng gì |
|---|---|
| Bug fix nhỏ | `/gsd:quick` |
| Config change | `/gsd:quick` |
| Feature nhỏ, domain quen | `/gsd:quick --full` |
| Feature phức tạp, domain mới | Full workflow (discuss → plan → execute → verify) |
| Hệ thống critical, production | Full workflow + `fine` granularity + `quality` profile |

### 12.4. Anti-Patterns — Tránh làm gì

| ❌ Anti-Pattern | ✅ Best Practice |
|---|---|
| Chấp nhận defaults qua Discuss quá nhanh | Trả lời chi tiết, mô tả vision cá nhân |
| Không `/clear` giữa phases | Clear context sau mỗi verify |
| Manual debug khi verify fail | Để GSD spawn debug agents |
| Re-run `/gsd:execute-phase` khi cần fix | Dùng `/gsd:quick` cho targeted fixes |
| Plans quá lớn (5+ tasks) | Giữ 2-3 tasks/plan, dùng `fine` granularity |
| Bỏ qua audit trước complete | LUÔN audit → plan gaps → complete |
